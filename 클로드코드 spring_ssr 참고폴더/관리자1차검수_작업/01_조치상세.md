### 조치
- **소스** `FileApiController.uploadFiles`:

  - import 추가: `LoginUserDTO`, `HttpSession`, `HttpStatus`. 메서드 Javadoc에 세션 체크 사유 명시.
  - `getFiles`(공개 첨부 조회)는 비로그인 열람이 정상이라 **의도적으로 인증 미추가**.
- **문서** `프로젝트_구조_정리.md` 적용 범위 표:
  - `/api/**` 각주를 "Interceptor 미적용 — Controller별 개별 인증"으로 변경.
  - 세부 정책 명시: 댓글 작성·수정·삭제 401 / 댓글 목록 GET 공개 / 파일 업로드 401 / 파일 목록·프록시 공개.

## L5. 고아 파일 24시간 유예가 문서 의도대로 동작하지 않음

### 재검증
- `FileRepository`의 `detachFiles`(45-47), `detachFilesByRefIds`(53-55)는 JPQL 벌크 `@Modifying` UPDATE → `FileEntity.@PreUpdate`(69-72) 미호출 → `updatedAt` 미갱신.
- 스케줄러는 `findByRefIdAndUpdatedAtBefore`로 `updatedAt < now-24h` 기준 삭제 → 실제 유예 기준이 "고아 시점"이 아닌 "업로드 시점"이 됨 확인.

### 조치 (소스)
- 두 detach 쿼리에 `f.updatedAt = CURRENT_TIMESTAMP` 추가:
  - `set f.refId = 0, f.updatedAt = CURRENT_TIMESTAMP where ...`
- 이로써 고아가 된 시점부터 24시간 유예가 성립 → `프로젝트_구조_정리.md:252` "updatedAt < 24시간 전" 기술과 정합.
- ※ `updateRefIdForIds`(글에 이미지 연결, refId를 실제 값으로)는 고아화가 아니므로 미변경. 각 쿼리 주석에 사유 기록.

## L6. 댓글 수정/삭제 시 `{communityId}` 경로 변수 미검증

- `CommentApiController` update(98-120)·delete(126-140)는 `commentId`만으로 처리, URL `communityId` 일치 미검증. 소유자 검증(`username`) 있어 보안 문제 아님(REST 정합성 이슈).
