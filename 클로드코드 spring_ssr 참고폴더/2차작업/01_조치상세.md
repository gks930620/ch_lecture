# 2차 작업 — 조치 상세

## 1. WebConfig exclude 버그 (2차검수 #1, 높음)

### 재검증

- `WebConfig.java:68`에 `excludePathPatterns(..., "/community/*", ...)` 실존 확인
- AntPathMatcher에서 `/community/*`는 한 세그먼트 와일드카드 → `/community/write` 매칭됨
- Spring `MappedInterceptor.matches()`는 exclude 패턴을 include보다 먼저 평가 → exclude에 걸리면 include에 있어도 인터셉터 미적용
- `CommunityController.write()(POST)`는 `loginUser.getId()` 호출 — 비로그인 시 `getLoginUser()`가 null 반환 → **NPE 확인** (검수 지적 그대로)
- `/community/*/edit`, `/community/*/delete`는 두 세그먼트라 `/community/*`에 안 걸림 — 검수 분석과 일치

### 조치

**소스** — `spring_ssr/src/main/java/com/ch/basic/common/config/WebConfig.java`
- exclude 목록 **전체 제거** (검수 제안대로 — include가 명시적 4개뿐이라 exclude는 전부 불필요했고 `/community/*`만 유해)
- 메서드 주석에 추가: "exclude는 include보다 우선 평가된다" + 과거 `/community/*` 버그 경위(교육 포인트·재발 방지)
- 메서드 끝 주석: 홈/목록/상세/정적 리소스는 include 미등록이라 exclude 없이도 적용 안 됨

**문서 동기화**
- `개념_07_Session_Login.md` 4-1장 — WebConfig 인용에서 exclude 제거, "명시 등록" 주석, ⚠️ exclude 우선순위 교육 포인트 블록(과거 버그 사례 포함) 신설
- `개념_11_Filter_Interceptor.md` — ① 5장 실제 코드 인용에서 exclude 제거 + 우선순위 주석 ② 4장 각주를 "`/**`처럼 넓게 걸 때는 css/js exclude 필요, 이 프로젝트는 명시 등록이라 불필요"로 정정 ③ 3장 등록 예시에 exclude 주의 문구
- `프로젝트_구조_정리.md` — 적용 범위 표 각주를 "현재 exclude 미사용 + 과거 버그 경위"로 갱신
