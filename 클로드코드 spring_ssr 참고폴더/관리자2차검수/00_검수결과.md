## 전체 검증

- **컴파일**: `JAVA_HOME=corretto-17.0.19 ./gradlew compileJava` — **관리자 직접 실행, exit 0** (작업자 주장 재현)
- **호출부 파급 영향**: 업로드 API의 유일한 호출처는 write.html:162·edit.html:180의 JS fetch. 두 화면 모두 Interceptor 보호 경로라 정상 흐름에서 세션이 항상 존재 → **동작 변화 없음**. 401 응답 시에도 `data.length`가 undefined라 조용히 무시(크래시 없음)
- **새로 쓴 문장 정확성**: XSS 섹션, /api/** 인증 정책 표, M4 교육 블록, L4 표 셀 — 전부 기술적으로 정확함을 확인

## 잔여 리스크 (참고 — 승인 조건 아님)

- **R1 (낮음)**: 업로드 401 시 JS(write/edit.html)가 alert 없이 조용히 무시 — 세션 만료 상태로 에디터에 이미지를 넣으면 아무 피드백이 없음. 정상 흐름에는 영향 없으므로 선택 개선(예: `if (res.status === 401) alert(...)`)
- **R2 (낮음)**: L5의 JPQL `CURRENT_TIMESTAMP`는 컴파일이 아닌 **앱 구동 시점**에 파싱 검증됨. 관리자 환경에서는 MariaDB(localhost:3406)가 내려가 있어 런타임 검증 불가 — 표준 JPQL 문법이라 위험은 낮으나, DB 기동 후 앱 1회 구동(또는 `gradlew test`)으로 확인 권장
