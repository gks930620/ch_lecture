## 2. CommunityController.delete() — 권한 체크 선행 (실제 버그 수정)

**검수 지적(06_총괄, 서비스설계 항목)**: 권한 체크가 마지막 `deleteCommunity()` 안에서만 수행되어, 작성자가 아닌 사용자가 삭제를 시도하면 **파일 고아 처리와 댓글 하드 삭제가 이미 실행된 뒤** 403이 발생 — 문서가 "위험"이라고 경고하는 시나리오가 실제로 재현되는 구조.

**수정**:
- `CommunityService`에 `validateOwner(communityId, username)` 추가 — 조회 + 작성자 검증만 수행 (클래스 레벨 readOnly 트랜잭션 적용)
- `delete()` 맨 앞(0번)에서 `validateOwner()` 호출 → 권한 없으면 파일/댓글에 손대기 전에 403
- Controller 주석에 "여러 Service 트랜잭션 없이 순차 호출의 한계 → 서비스설계_정리.md 참고, 정석은 Facade + @Transactional" 안내 추가
- 기존 `deleteCommunity()` 내부 권한 체크는 유지 (이중 방어 + 기존 학습 코드 보존)

※ Facade 도입(트랜잭션으로 묶기)은 강의 구조를 바꾸는 큰 변경이라 이번엔 하지 않고, 문서(서비스설계_정리.md)에 개선 방향으로 연결만 해둠 — 필요하면 다음 차수에서 논의.
