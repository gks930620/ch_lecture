### [10] ⚪ KAKAO id 캐스팅 견고화 → 해결
- **파일**: `user/OAuthProvider.java`
- `Long id = (Long) attributes.get("id")` → `String id = String.valueOf(attributes.get("id"))`.
- `username`은 어차피 `provider + id` 문자열이라 캐스팅 불필요. Integer로 올 경우의 `ClassCastException` 방지.

### [8][9] ⚪ 보안 교육 노트(주석) 추가 → 반영
- **파일**: `common/config/SecurityConfig.java`
- `hasAuthority` vs `hasRole`(ROLE_ 접두어) 차이, `anyRequest().permitAll()`의 실무 관례(화이트리스트) 주석 추가.
- 코드 동작은 변경하지 않음(정상 동작 중). 설명만 보강.

### [3] 🟡 무관 보일러플레이트 → 안내 주석 추가(코드 미삭제)
- **파일**: `application.yml`
- 파일 업로드(`servlet.multipart`, `file.upload-dir`), `default_batch_fetch_size` 옆에
  "이 로그인 예제에서는 미사용 / 공용 보일러플레이트" 주석 추가.
- **삭제하지 않은 이유**: QueryDSL 빌드 설정·소프트삭제 제거는 스코프가 크고 강의 설계 의도(공용 템플릿 유지) 판단이 필요 → 검수자 제안 중 **저위험 옵션(안내 명시)** 선택.

### [4] 🟡 프로젝트_구조_정리.md 범용 원칙 문서 → 안내 헤더 추가
- **파일**: `docs/spring_ssr_security_oauth2/프로젝트_구조_정리.md`
- 문서 최상단에 "이 문서는 여러 프로젝트 공유 범용 원칙이며, 본 로그인 프로젝트엔 게시글·댓글·파일 도메인이 없다"는 안내 추가.
- 원문(댓글/글/Facade 예시)은 삭제하지 않고 "일반 원칙 참고용"으로 안내.

### [7] 🟢 data-users.sql 이중 정의 → 안내 주석 추가
- **파일**: `resources/data-users.sql`
- ddl-auto:create + SQL DROP/CREATE의 **스키마 이중 정의** 및 "Entity 변경 시 SQL도 함께 수정" 함정을 주석으로 명시.
- INSERT-only 리팩터(옵션1) 대신 **스키마 가시성 유지 + 주석 경고**(옵션2) 선택 — 컬럼 불일치 리스크 회피.

### 추가: DB 계정 평문 → 교육 노트

  (OAuth 키만 .env로 빼고 DB는 평문이던 불일치 보완).

## ⚠️ 사이드 이펙트 / 주의

- **이미지**: docs와 소스 양쪽에 동일 이미지 8장이 존재(중복). 정리하려면 소스 쪽을 심볼릭/삭제 결정 필요.
- **OAuthProvider**: `id` 타입이 `Long` → `String`으로 변경됨. 이후 이 값을 숫자로 쓰는 코드가 추가되면 파싱 필요(현재는 문자열 연결만 사용 → 영향 없음).
- 코드 로직 변경은 [10] 한 건뿐이며 동작 결과 동일(username 문자열 값 불변). 나머지는 주석·문서·리소스 배치 변경.
