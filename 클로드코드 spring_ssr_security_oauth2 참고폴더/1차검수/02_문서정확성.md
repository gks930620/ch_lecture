## 🟢 [5] mypage.html 주석의 타입명 오기

**파일**: `templates/mypage.html` 66~67행

```html
<!-- ※ 이 페이지는 로그인 필수(Security가 비로그인 시 /login 리다이렉트)이므로
        user(CustomUserDetails)가 항상 존재함 → sec:authorize 분기 불필요 -->
```

- 실제 principal 타입은 **`CustomUserAccount`** 입니다 (`CustomUserDetails`라는 클래스는 이 프로젝트에 없음).
- 초심자가 `CustomUserDetails`라는 클래스를 찾다가 혼란할 수 있습니다.
- **조치**: `CustomUserDetails` → `CustomUserAccount`로 정정.

## 🟢 [6] `client-authentication-method` 설명이 문서 간 미묘하게 다름

두 문서와 yml 주석의 설명 뉘앙스가 다릅니다. **셋 다 "카카오는 none이 맞다"는 결론은 동일**하지만, "기본값이 무엇인지"에 대한 서술이 갈립니다.

| 위치 | 서술 |
|------|------|
| `security oauth2 설명.md` (237행) | "기본값 `client_secret_basic`이 적용되면 **401 에러**" (단정) |
| `security oauth2 설명_back.md` (180행) | "Spring Boot 3.4+ 에서는 secret 없으면 **자동 none**, 3.3 이하만 명시 필요" |
| `application.yml` (88행 주석) | "3.4+ 에서는 자동 none이지만 **명시적으로 설정 권장**" (가장 정확) |

- 이 프로젝트는 **Spring Boot 3.4.2** 이고, `none`을 **명시**하고 있으므로 동작에는 문제가 없습니다.
- 다만 초심자가 두 문서를 같이 보면 "기본값이 basic이라 무조건 401 난다"(설명.md)와 "3.4+는 자동 none이라 괜찮다"(back.md)가 상충되어 보입니다.
- **조치**: 세 곳을 yml 주석 기준으로 통일 권장 →
  *"카카오는 client_secret이 없어 인증방식이 `none`이어야 한다. 버전에 따라 자동으로 잡히기도 하지만, 버전 무관하게 안전하도록 `none`을 명시한다."*

> 참고: `_back.md`는 이름상 백업/이전본으로 보입니다. 최신본은 `security oauth2 설명.md`이므로, 둘 중 하나만 유지할지(중복 관리 부담) 결정하는 것도 고려하세요.

## 🟢 [7] `data-users.sql`이 `ddl-auto: create`와 테이블을 이중 정의

**파일**: `resources/data-users.sql`, `resources/application.yml`

- `ddl-auto: create`(yml 32행) → Hibernate가 **UserEntity 기준으로 users 테이블을 생성**합니다.
- 그 직후 `data-users.sql`(defer-datasource-initialization: true)이 **다시 `DROP TABLE ... CREATE TABLE`** 로 재정의합니다.
- 즉 테이블 스키마가 **두 곳(Entity + SQL)에서 이중 정의**되고, 최종적으로는 SQL 쪽이 이깁니다.

현재는 컬럼이 서로 일치하여 **정상 동작**하지만:
- `UserEntity`에 컬럼을 추가/변경하면 `data-users.sql`의 `CREATE TABLE`도 **수동으로 맞춰줘야** 합니다 (초심자가 놓치기 쉬운 함정).
- SQL 상단 주석은 "이전 스키마 잔재 제거용"이라 설명하지만, `ddl-auto: create`가 이미 매번 drop/create 하므로 SQL의 수동 DROP/CREATE는 상당 부분 중복입니다.

**조치 제안 (택1)**
1. `data-users.sql`에서 `DROP/CREATE TABLE`을 빼고 **`INSERT`만** 남긴다 (테이블 생성은 Hibernate에 일임). → 이중 정의 해소.
2. 이중 정의를 유지한다면, 문서/주석에 "**스키마 변경 시 Entity와 data-users.sql을 함께 수정해야 함**"을 명시.

> 두 방안 모두 유효합니다. 강의 흐름상 "JPA가 테이블을 만든다"를 강조하려면 1안이 더 깔끔합니다.
