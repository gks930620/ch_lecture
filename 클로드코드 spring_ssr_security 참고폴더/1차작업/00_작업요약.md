## 보류 사유 (검수 #6 일부 — 미사용 보일러플레이트 삭제)

QueryDSL 설정/의존성, 파일 업로드 설정, 공공데이터 API 키, aop/validation 의존성,
`@EnableScheduling` 등은 **실제로 이번 강의(세션 로그인)와 무관한 잔재가 맞다.**
다만 이번 1차 작업에서는 **삭제하지 않고 보류**했다. 이유:

1. `build.gradle`에서 QueryDSL을 제거하면 `QuerydslConfig.java`, 생성된 QClass,
   `sourceSets` 설정까지 연쇄로 정리해야 하고, 잘못 건드리면 빌드가 깨질 위험이 있다.
2. 동작에는 지장이 없고(검수도 "동작엔 지장 없음"으로 분류), 삭제는 되돌리기 어려운
   범위라 **사용자(개발자) 확인 후** 별도 세션에서 일괄 정리하는 것이 안전하다.

대신 **초보자에게 직접 혼란/404를 주는 `index.html`의 죽은 링크·없는 기능 카드**는
이번에 수정했다 (검수 #6에서 가장 체감 큰 부분).

→ **다음 세션 권장 작업**: build.gradle/QuerydslConfig/application.yml의
   파일업로드·api.service-key 블록·@EnableScheduling 제거 여부를 사용자와 확인 후 정리.

## 주의 / 사이드 이펙트

- **컴파일 검증 못 함**: 이 작업 환경에 JDK가 없어(`java`/`JAVA_HOME` 부재)
  `./gradlew compileJava`를 실행하지 못했다. 다만 `SimpleGrantedAuthority`는
  Spring Security 코어 표준 클래스(`org.springframework.security.core.authority`)라
  import 경로 및 사용법은 정확하다. 다음 세션 또는 로컬에서 빌드 1회 확인 권장.
- 테스트 yml을 `test` DB 기준으로 교체했으므로, 테스트 실행에는 로컬 MariaDB(`test`)가
  필요하다 (main 설정과 동일 전제). 검수가 지적한 "존재하지 않는 SQL 참조"는 제거됨.
- 이미지는 `docs/spring_ssr_security/spring_ssr_security_images/`로 **복사**(원본 유지).
  경로는 java_basic과 동일한 Jekyll `relative_url` 방식으로 통일.
