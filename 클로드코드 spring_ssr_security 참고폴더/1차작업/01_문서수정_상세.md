# 01. 문서 수정 상세 (docs/spring_ssr_security)

## <a id="1"></a>#1 🔴 BCrypt "자동 디코딩" 오설명 수정

- 파일: `docs/spring_ssr_security/security설명.md`
- BCrypt는 단방향 해시라 "디코딩(복호화)"이 존재하지 않음. 초보자에게 잘못된 개념 주입.
- 같은 프로젝트 `SecurityConfig.java:23` 코드 주석은 이미 올바르게 설명 → 문서를 코드 수준으로 맞춤.

```diff
- @Bean  // 비밀번호를 BCrypt로 인코딩해서 DB에 저장, 비교 시 자동 디코딩
+ @Bean  // 회원가입 시 encode()로 해시 저장, 로그인 시 matches()로 해시 비교 (단방향 — 복호화 불가)
```

## <a id="3"></a>#3 🟠 클래스명 불일치 수정 (CustomUserDetails → CustomUserAccount)

- 파일: `docs/spring_ssr_security/프로젝트_구조_정리.md`
- 실제 클래스명은 `CustomUserAccount`. 이 문서만 `CustomUserDetails`로 잘못 부름.
- **주의**: `CustomUserDetailsService`는 실제 존재하는 별개 클래스이므로 그대로 둠 (치환 대상 아님).
- 수정 위치: 라인 49, 65, 69, 70, 95, 97, 112 (총 5개 문맥, `~Service` 제외).

```diff
- public String mypage(@AuthenticationPrincipal CustomUserDetails userDetails, Model model) {
+ public String mypage(@AuthenticationPrincipal CustomUserAccount userDetails, Model model) {
```

## <a id="7-1"></a>#7-1 ⚪ UserDetails default 메소드 시점 정정

- 파일: `docs/spring_ssr_security/security설명.md` (CustomUserAccount 코드블록 하단 주석)
- "Spring Boot 3부터" → "Spring Security 6.1(= Spring Boot 3.1)부터"로 정정.
  Boot 3.0(Security 6.0)에는 default 메소드가 없었음. 이 프로젝트는 Boot 3.3.4라 해당됨.

```diff
- // → Spring Boot 3부터는 default 메소드로 제공되어 구현 생략 가능
+ // → Spring Security 6.1(= Spring Boot 3.1)부터 UserDetails의 default 메소드로 제공되어 구현 생략 가능
+ //   (이 프로젝트는 Boot 3.3.4라 해당됨. Boot 3.0에서는 직접 구현해야 했음)
```

> ※ #7-2(getAuthorities 람다 → SimpleGrantedAuthority)는 코드 변경을 동반하므로
>   security설명.md의 해당 코드블록/주석도 함께 수정했다. 상세는 `02_소스수정_상세.md#7-2` 참고.
