# ch10 자바API — 문제 예시 답안

> 답은 한 가지가 아닙니다. 아래는 예시 답안이며, 스스로 푼 뒤에 비교해 보세요.

## A. 날짜/시간 API

### A-1. 오늘 기준 100일 뒤 날짜

```java
import java.time.LocalDate;

public class After100DaysDemo {
    public static void main(String[] args) {
        LocalDate today = LocalDate.now();
        LocalDate after100 = today.plusDays(100);

        System.out.println("오늘: " + today);        // 오늘: 2026-07-03 (실행 시점에 따라 다름)
        System.out.println("100일 뒤: " + after100); // 100일 뒤: 2026-10-11 (실행 시점에 따라 다름)
    }
}
```

**핵심 포인트**: `java.time` 타입은 불변이므로 `plusDays(100)`은 `today`를 바꾸지 않고 새 객체를 반환한다. 반환값을 받지 않으면 아무 일도 일어나지 않는다.

### A-2. 생년월일로 현재 나이 계산

```java
import java.time.LocalDate;
import java.time.Period;

public class AgeDemo {
    public static void main(String[] args) {
        LocalDate birth = LocalDate.of(2000, 5, 10);
        LocalDate today = LocalDate.now();

        Period period = Period.between(birth, today);
        System.out.println("만 나이: " + period.getYears() + "세"); // 만 나이: 26세 (실행 시점에 따라 다름)
        System.out.println("정확히: " + period.getYears() + "년 "
                + period.getMonths() + "개월 " + period.getDays() + "일");
        // 정확히: 26년 1개월 23일 (실행 시점에 따라 다름)
    }
}
```

**핵심 포인트**: 날짜 단위 차이는 `Period.between(과거, 미래)`이 정석이다. `getYears()`가 생일 경과 여부까지 반영한 만 나이가 된다.

### A-3. 두 LocalDateTime 차이를 Duration으로 계산

```java
import java.time.Duration;
import java.time.LocalDateTime;

public class DurationDemo {
    public static void main(String[] args) {
        LocalDateTime start = LocalDateTime.of(2026, 4, 20, 9, 0, 0);
        LocalDateTime end = LocalDateTime.of(2026, 4, 21, 14, 30, 0);

        Duration d = Duration.between(start, end);
        System.out.println("총 시간: " + d.toHours() + "시간");          // 총 시간: 29시간
        System.out.println(d.toDays() + "일 " + d.toHoursPart() + "시간 "
                + d.toMinutesPart() + "분");                             // 1일 5시간 30분
    }
}
```

**핵심 포인트**: 시간 단위 간격은 `Duration`, 날짜 단위 기간은 `Period`로 구분한다. `toHours()`는 전체 환산값, `toHoursPart()`는 일수를 뺀 나머지 부분이다.

### A-4. UTC Instant를 Asia/Seoul 시간으로 변환

```java
import java.time.Instant;
import java.time.ZoneId;
import java.time.ZonedDateTime;

public class ZoneConvertDemo {
    public static void main(String[] args) {
        Instant nowUtc = Instant.parse("2026-04-09T00:00:00Z"); // 절대 시점(UTC)
        ZonedDateTime seoul = nowUtc.atZone(ZoneId.of("Asia/Seoul"));

        System.out.println("UTC 시점 : " + nowUtc);  // UTC 시점 : 2026-04-09T00:00:00Z
        System.out.println("서울 표시: " + seoul);   // 서울 표시: 2026-04-09T09:00+09:00[Asia/Seoul]
    }
}
```

**핵심 포인트**: `Instant`는 타임존 없는 절대 시점, `atZone(ZoneId)`을 붙이는 순간 "그 지역에서 보이는 시각"이 된다. 서울은 UTC+9이므로 9시간 뒤로 표시된다. 저장은 Instant(UTC), 표시는 ZoneId 변환이 기본 전략이다.

## B. 포맷팅/파싱

### B-1. yyyy-MM-dd HH:mm:ss 패턴으로 현재 시각 출력

```java
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

public class FormatDemo {
    public static void main(String[] args) {
        DateTimeFormatter f = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
        String text = LocalDateTime.now().format(f);
        System.out.println(text); // 2026-07-03 10:15:30 (실행 시점에 따라 다름)
    }
}
```

**핵심 포인트**: `MM`은 월, `mm`은 분, `HH`는 24시간제 시. 대소문자를 혼동하면 컴파일은 되지만 엉뚱한 값이 출력된다.

### B-2. 문자열을 LocalDateTime으로 파싱

```java
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

public class ParseDemo {
    public static void main(String[] args) {
        DateTimeFormatter f = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
        LocalDateTime parsed = LocalDateTime.parse("2026-04-09 15:30:00", f);

        System.out.println(parsed);              // 2026-04-09T15:30
        System.out.println(parsed.getHour());    // 15
    }
}
```

**핵심 포인트**: 파싱할 문자열의 형식과 포맷터 패턴이 정확히 일치해야 한다. 기본 `toString()`은 ISO-8601 형식(`T` 구분자)으로 출력되며, 초가 0이면 생략된다.

### B-3. 파싱 실패 시 예외 처리 + 사용자 안내

```java
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;

public class ParseErrorDemo {
    public static void main(String[] args) {
        DateTimeFormatter f = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
        String input = "2026/04/09 15:30:00"; // 잘못된 구분자

        try {
            LocalDateTime parsed = LocalDateTime.parse(input, f);
            System.out.println("파싱 결과: " + parsed);
        } catch (DateTimeParseException e) {
            System.out.println("날짜 형식이 올바르지 않습니다: " + input);
            System.out.println("yyyy-MM-dd HH:mm:ss 형식으로 입력해 주세요. (예: 2026-04-09 15:30:00)");
        }
    }
}
// 출력:
// 날짜 형식이 올바르지 않습니다: 2026/04/09 15:30:00
// yyyy-MM-dd HH:mm:ss 형식으로 입력해 주세요. (예: 2026-04-09 15:30:00)
```

**핵심 포인트**: 형식이 어긋나면 `DateTimeParseException`(unchecked)이 발생한다. 사용자 안내에는 "무엇이 잘못됐는지 + 올바른 예시"를 함께 보여주는 것이 좋다.

## C. 문자열 처리

### C-1. 앞뒤 공백 제거 + 소문자 정규화

```java
public class NormalizeDemo {
    public static void main(String[] args) {
        String input = "  Hello Java  ";
        String normalized = input == null ? "" : input.strip().toLowerCase();

        System.out.println("[" + normalized + "]"); // [hello java]
    }
}
```

**핵심 포인트**: 문자열은 불변이므로 `strip().toLowerCase()`는 원본을 바꾸지 않고 새 문자열을 반환한다. `strip`(Java 11+)은 `trim`보다 유니코드 공백까지 처리한다. null 방어를 함께 하는 습관이 중요하다.

### C-2. 이메일 형식 검증(정규표현식)

```java
public class EmailValidateDemo {
    static final String EMAIL_REGEX = "^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}$";

    public static void main(String[] args) {
        String[] inputs = {"kim@test.com", "hello@dev.co.kr", "bad-email", "a@b", "@no-local.com"};
        for (String s : inputs) {
            System.out.println(s + " -> " + s.matches(EMAIL_REGEX));
        }
    }
}
// 출력:
// kim@test.com -> true
// hello@dev.co.kr -> true
// bad-email -> false
// a@b -> false
// @no-local.com -> false
```

**핵심 포인트**: `matches`는 문자열 전체가 패턴과 일치해야 true다. 자바 문자열 리터럴에서 정규식의 `\.`는 `\\.`로 이스케이프해야 한다.

### C-3. CSV 한 줄 split

```java
public class CsvSplitDemo {

// 출력:
// 필드[0] = 1001
// 필드[1] = 김자바
// 필드[2] = kim@test.com

```

**핵심 포인트**: `split`의 인자는 정규식이다. 쉼표는 괜찮지만 `split(".")`처럼 메타문자를 쓰면 의도와 다르게 동작하므로 `split("\\.")`로 이스케이프해야 한다.

### C-4. 문자열 뒤집기와 회문 판별

```java
public class PalindromeDemo {
    public static void main(String[] args) {
        System.out.println(reverse("java"));       // avaj
        System.out.println(isPalindrome("level")); // true
        System.out.println(isPalindrome("Level")); // true (대소문자 무시)
        System.out.println(isPalindrome("java"));  // false
    }

    static String reverse(String s) {
        return new StringBuilder(s).reverse().toString();
    }

    static boolean isPalindrome(String s) {
        String normalized = s.toLowerCase();
        return normalized.equals(reverse(normalized));
    }
}
```

**핵심 포인트**: `String`에는 reverse가 없고 `StringBuilder.reverse()`를 이용한다. 회문 판별 전 소문자 정규화처럼 "비교 전 정규화" 습관이 실무 포인트다.

## D. StringBuilder 성능

### D-1 ~ D-2. `+` 방식 vs StringBuilder 방식 + 시간 측정 비교

```java
public class ConcatBenchmark {
    public static void main(String[] args) {
        int n = 100_000;

        // 방식 1: + 연결 (매 반복마다 새 String 생성)
        long start1 = System.nanoTime();
        String plusResult = "";
        for (int i = 1; i <= n; i++) {
            plusResult += i;
        }
        long time1 = System.nanoTime() - start1;

        // 방식 2: StringBuilder (내부 버퍼에 누적)
        long start2 = System.nanoTime();
        StringBuilder sb = new StringBuilder();
        for (int i = 1; i <= n; i++) {
            sb.append(i);
        }
        String sbResult = sb.toString();
        long time2 = System.nanoTime() - start2;

        System.out.println("결과 동일 여부: " + plusResult.equals(sbResult)); // 결과 동일 여부: true
        System.out.println("+ 방식        : " + time1 / 1_000_000 + " ms"); // 예: 4500 ms (실행 환경에 따라 다름)
        System.out.println("StringBuilder : " + time2 / 1_000_000 + " ms"); // 예: 3 ms (실행 환경에 따라 다름)
        System.out.println("결과 길이: " + sbResult.length());               // 결과 길이: 488895
    }
}
```

**핵심 포인트**: `+`는 반복마다 기존 내용 전체를 복사한 새 문자열을 만들어 O(n²)이 되고, `StringBuilder`는 내부 버퍼에 이어 붙여 O(n)이다. 10만 회 기준 수백~수천 배 차이가 난다(정확한 수치는 실행 환경에 따라 다름).

## E. 파일 I/O

### E-1 ~ E-3. UTF-8로 저장 → 라인 단위 읽기 (try-with-resources)

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

public class FileWriteReadDemo {
    public static void main(String[] args) {
        Path path = Path.of("members.txt");

        // E-1: UTF-8 명시하여 저장 (E-3: try-with-resources로 자원 해제 보장)
        try (BufferedWriter bw = Files.newBufferedWriter(path, StandardCharsets.UTF_8)) {
            bw.write("김자바,28");
            bw.newLine();
            bw.write("이코딩,31");
            bw.newLine();
        } catch (IOException e) {
            System.out.println("저장 실패: " + e.getMessage());
            return;
        }

        // E-2: 라인 단위로 읽어 출력 (UTF-8 명시)
        try (BufferedReader br = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
            String line;
            int no = 1;
            while ((line = br.readLine()) != null) {
                System.out.println(no++ + ": " + line);
            }
        } catch (IOException e) {
            System.out.println("읽기 실패: " + e.getMessage());
        }
    }
}
// 출력:
// 1: 김자바,28
// 2: 이코딩,31
```

**핵심 포인트**: 쓰기/읽기 모두 `StandardCharsets.UTF_8`을 명시해야 플랫폼 기본 인코딩에 따른 한글 깨짐을 막는다. try-with-resources 덕분에 close 호출이 코드에 등장하지 않는다.

### E-4. 파일이 없을 때 예외 처리

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.NoSuchFileException;
import java.nio.file.Path;

public class FileNotFoundDemo {
    public static void main(String[] args) {
        Path path = Path.of("no_such_file.txt");

        try (BufferedReader br = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
            System.out.println(br.readLine());
        } catch (NoSuchFileException e) {
            System.out.println("파일을 찾을 수 없습니다: " + e.getFile());
            System.out.println("경로를 확인한 뒤 다시 시도해 주세요.");
        } catch (IOException e) {
            System.out.println("파일 읽기 중 오류: " + e.getMessage());
        }
    }
}
// 출력:
// 파일을 찾을 수 없습니다: no_such_file.txt
// 경로를 확인한 뒤 다시 시도해 주세요.
```

**핵심 포인트**: `NoSuchFileException`은 `IOException`의 하위 타입이므로 더 구체적인 것을 먼저 catch한다. "파일 없음"과 "기타 I/O 오류"를 구분하면 사용자 안내가 정확해진다.

## F. 응용 문제

### F-1. 로그 파일에서 ERROR 라인만 추출해 별도 파일로 저장

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

public class ErrorLogExtractor {
    public static void main(String[] args) {
        Path source = Path.of("app.log");
        Path target = Path.of("errors.log");

        try {
            // 테스트용 로그 파일 준비
            Files.writeString(source, """
                    2026-07-03 10:00:01 INFO 서버 시작
                    2026-07-03 10:00:05 ERROR DB 연결 실패
                    2026-07-03 10:00:06 INFO 재시도
                    2026-07-03 10:00:10 ERROR 타임아웃
                    """, StandardCharsets.UTF_8);

            int count = 0;
            try (BufferedReader br = Files.newBufferedReader(source, StandardCharsets.UTF_8);
                 BufferedWriter bw = Files.newBufferedWriter(target, StandardCharsets.UTF_8)) {
                String line;
                while ((line = br.readLine()) != null) {
                    if (line.contains("ERROR")) {
                        bw.write(line);
                        bw.newLine();
                        count++;
                    }
                }
            }
            System.out.println("추출된 ERROR 라인 수: " + count);
            Files.readAllLines(target, StandardCharsets.UTF_8).forEach(System.out::println);
        } catch (IOException e) {
            System.out.println("로그 처리 실패: " + e.getMessage());
        }
    }
}
// 출력:
// 추출된 ERROR 라인 수: 2
// 2026-07-03 10:00:05 ERROR DB 연결 실패
// 2026-07-03 10:00:10 ERROR 타임아웃
```

**핵심 포인트**: try-with-resources는 자원을 `;`로 여러 개 선언할 수 있고 선언 역순으로 자동 close된다. 라인 단위 스트리밍이라 대용량 로그에도 메모리 부담이 없다.

### F-2. D-day 계산 콘솔 앱

```java
import java.time.LocalDate;
import java.time.format.DateTimeParseException;
import java.time.temporal.ChronoUnit;
import java.util.Scanner;

public class DdayApp {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("목표 날짜를 입력하세요 (yyyy-MM-dd): ");
        String input = sc.nextLine().strip();

        try {
            LocalDate target = LocalDate.parse(input); // 기본 ISO 형식 yyyy-MM-dd
            long days = ChronoUnit.DAYS.between(LocalDate.now(), target);

            if (days > 0) {
                System.out.println("D-" + days);
            } else if (days == 0) {
                System.out.println("D-Day 당일입니다!");
            } else {
                System.out.println("이미 " + (-days) + "일 지났습니다 (D+" + (-days) + ")");
            }
        } catch (DateTimeParseException e) {
            System.out.println("날짜 형식이 올바르지 않습니다. 예: 2026-12-25");
        }
    }
}
// 실행 예 (2026-07-03에 실행했다고 가정, 실행 시점에 따라 다름):
// 목표 날짜를 입력하세요 (yyyy-MM-dd): 2026-12-25
// D-175
```

**핵심 포인트**: `yyyy-MM-dd`는 ISO 기본 형식이라 포맷터 없이 `LocalDate.parse`가 가능하다. 남은 일수는 `ChronoUnit.DAYS.between(오늘, 목표)`로 계산하며 목표가 과거면 음수가 된다.

### F-3. 회원 CSV를 객체 리스트로 변환

```java
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.ArrayList;
import java.util.List;

record Member(long id, String name, String email, int age) {
    static Member fromCsv(String line) {
        String[] f = line.split(",");
        return new Member(Long.parseLong(f[0].strip()), f[1].strip(),
                f[2].strip(), Integer.parseInt(f[3].strip()));
    }
}

public class CsvToObjectDemo {
    public static void main(String[] args) {
        Path path = Path.of("members.csv");
        try {
            // 테스트용 CSV 준비 (UTF-8 명시)
            Files.writeString(path, """
                    1001,김자바,kim@test.com,28
                    1002,이코딩,lee@test.com,31
                    1003,박개발,park@test.com,25
                    """, StandardCharsets.UTF_8);

            List<Member> members = new ArrayList<>();
            for (String line : Files.readAllLines(path, StandardCharsets.UTF_8)) {
                if (line.isBlank()) continue; // 빈 줄 방어
                members.add(Member.fromCsv(line));
            }

            for (Member m : members) {
                System.out.println(m.name() + " (" + m.age() + "세) - " + m.email());
            }
        } catch (IOException e) {
            System.out.println("CSV 처리 실패: " + e.getMessage());
        }
    }
}
// 출력:
// 김자바 (28세) - kim@test.com
// 이코딩 (31세) - lee@test.com
// 박개발 (25세) - park@test.com
```

**핵심 포인트**: "한 줄 → 객체" 변환 로직을 `fromCsv` 같은 정적 팩토리로 분리하면 파싱 규칙이 한 곳에 모인다. Java 17의 record는 이런 데이터 운반용 타입에 딱 맞는다.

### G-1. 서울과 뉴욕의 현재 시각 동시 출력

```java
import java.time.Instant;
import java.time.ZoneId;
import java.time.ZonedDateTime;
import java.time.format.DateTimeFormatter;

public class TwoZonesDemo {
    public static void main(String[] args) {
        Instant now = Instant.now(); // 같은 절대 시점을 기준으로
        DateTimeFormatter f = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

        ZonedDateTime seoul = now.atZone(ZoneId.of("Asia/Seoul"));
        ZonedDateTime newYork = now.atZone(ZoneId.of("America/New_York"));

        System.out.println("서울: " + seoul.format(f));  // 서울: 2026-07-03 21:00:00 (실행 시점에 따라 다름)
        System.out.println("뉴욕: " + newYork.format(f)); // 뉴욕: 2026-07-03 08:00:00 (실행 시점에 따라 다름)
        // 같은 순간이지만 서울(UTC+9)과 뉴욕(UTC-4, 서머타임 적용 시)의 표시가 13시간 차이난다
    }
}
```

**핵심 포인트**: `Instant.now()`를 한 번만 호출해 같은 절대 시점을 두 타임존으로 변환해야 "동시각" 비교가 된다. 뉴욕은 서머타임(DST) 때문에 UTC-5/UTC-4를 오가는데, ZoneId가 이를 자동 처리한다.

### G-2. 대용량 텍스트 파일 단어 빈도수 계산

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.HashMap;
import java.util.Map;

public class WordCountDemo {
    public static void main(String[] args) {
        Path path = Path.of("big.txt");
        try {
            // 테스트용 파일 준비 (UTF-8 명시)
            Files.writeString(path, """
                    java is fun
                    Java is powerful
                    fun fun coding
                    """, StandardCharsets.UTF_8);

            Map<String, Integer> freq = new HashMap<>();
            // 대용량 대비: 전체를 메모리에 올리지 않고 라인 단위 스트리밍
            try (BufferedReader br = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
                String line;
                while ((line = br.readLine()) != null) {
                    for (String word : line.toLowerCase().split("\\s+")) {
                        if (word.isBlank()) continue;
                        freq.merge(word, 1, Integer::sum);
                    }
                }
            }

            freq.entrySet().stream()
                    .sorted(Map.Entry.<String, Integer>comparingByValue().reversed())
                    .forEach(e -> System.out.println(e.getKey() + ": " + e.getValue()));
        } catch (IOException e) {
            System.out.println("파일 처리 실패: " + e.getMessage());
        }
    }
}
// 출력:
// fun: 3
// java: 2
// is: 2
// powerful: 1
// coding: 1
```

**핵심 포인트**: 대용량의 핵심은 `readAllLines`(전체 로딩) 대신 `BufferedReader`로 라인 단위 처리해 메모리 사용을 상수로 유지하는 것이다. `merge(word, 1, Integer::sum)`은 "없으면 1, 있으면 +1"을 한 줄로 처리한다.

### G-3. IOException을 도메인 예외로 변환해 전파

```java
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

// 도메인 예외: unchecked + cause 보존
class FileProcessingException extends RuntimeException {
    public FileProcessingException(String message, Throwable cause) {
        super(message, cause);
    }
}

public class TranslateIoExceptionDemo {
    public static void main(String[] args) {
        try {
            List<String> lines = loadReport(Path.of("no_such_report.txt"));
            lines.forEach(System.out::println);
        } catch (FileProcessingException e) {
            // 최상위: 사용자 안내 + 개발자 로그(cause 포함)
            System.out.println("[안내] 보고서를 불러오지 못했습니다. 관리자에게 문의하세요.");
            System.out.println("[LOG] " + e.getMessage() + " / cause=" + e.getCause());
        }
    }

    // 기술 예외(IOException)를 도메인 예외로 변환해 전파
    static List<String> loadReport(Path path) {
        try {
            return Files.readAllLines(path, StandardCharsets.UTF_8);
        } catch (IOException e) {
            throw new FileProcessingException("보고서 파일 처리 실패: " + path, e);
        }
    }
}
// 출력:
// [안내] 보고서를 불러오지 못했습니다. 관리자에게 문의하세요.
// [LOG] 보고서 파일 처리 실패: no_such_report.txt / cause=java.nio.file.NoSuchFileException: no_such_report.txt
```

**핵심 포인트**: 변환 시 원인 예외를 cause로 반드시 넘겨야(`new FileProcessingException(msg, e)`) 근본 원인이 스택트레이스에 보존된다. 호출자는 IOException이라는 기술 세부사항 대신 도메인 관점의 예외만 다루면 된다.
