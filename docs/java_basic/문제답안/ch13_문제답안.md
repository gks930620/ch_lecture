# ch13 람다와 함수형 — 문제 예시 답안

> 답은 한 가지가 아닙니다. 아래는 예시 답안이며, 스스로 푼 뒤에 비교해 보세요.

## A. 람다 기초

### A-1. `Calculator` 함수형 인터페이스 + 덧셈 람다

추상 메소드가 하나인 인터페이스는 람다의 타겟 타입이 될 수 있으므로, `int calc(int, int)` 하나만 선언하면 됩니다.

```java
@FunctionalInterface
interface Calculator {
    int calc(int a, int b);
}

public class A1 {
    public static void main(String[] args) {
        Calculator add = (a, b) -> a + b;
        System.out.println(add.calc(3, 4)); // 7
    }
}
```

```text
// 출력
7
```

### A-2. 같은 인터페이스로 뺄셈/곱셈/나눗셈 람다

같은 함수형 인터페이스에 서로 다른 람다를 대입하는 것만으로 "동작 교체"가 됩니다. 전략 패턴을 클래스 없이 구현하는 셈입니다.

```java
@FunctionalInterface
interface Calculator {
    int calc(int a, int b);
}

public class A2 {
    public static void main(String[] args) {
        Calculator sub = (a, b) -> a - b;
        Calculator mul = (a, b) -> a * b;
        Calculator div = (a, b) -> {
            if (b == 0) throw new ArithmeticException("0으로 나눌 수 없습니다");
            return a / b;
        };

        System.out.println(sub.calc(10, 3)); // 7
        System.out.println(mul.calc(10, 3)); // 30
        System.out.println(div.calc(10, 3)); // 3 (정수 나눗셈)
    }
}
```

```text
// 출력
7
30
3
```

### A-3. 익명 클래스 vs 람다 비교

동일한 `Comparator` 구현을 두 방식으로 작성해 비교합니다. 람다는 "메소드 시그니처가 이미 인터페이스에 있으니, 본문만 쓰자"는 발상입니다.

```java
import java.util.Comparator;

public class A3 {
    public static void main(String[] args) {
        // 1) 익명 클래스: 타입/메소드 선언이 반복됨
        Comparator<String> anon = new Comparator<String>() {
            @Override
            public int compare(String a, String b) {
                return a.length() - b.length();
            }
        };

        // 2) 람다: 본문만 남음
        Comparator<String> lambda = (a, b) -> a.length() - b.length();

        System.out.println(anon.compare("abc", "a"));   // 2
        System.out.println(lambda.compare("abc", "a")); // 2

        // 차이 요약
        // - 익명 클래스: 자체 this(익명 클래스 인스턴스), 새 스코프, 클래스 파일 생성
        // - 람다: this가 바깥 클래스, 스코프 공유, invokedynamic 기반 (더 가벼움)
    }
}
```

```text
// 출력
2
2
```

## B. 표준 함수형 인터페이스

### B-1. `Predicate<String>`로 빈 문자열 필터

"T를 받아 boolean 판정"이 필요하므로 `Predicate`가 정확한 선택입니다.

```java
import java.util.List;
import java.util.function.Predicate;

public class B1 {
    public static void main(String[] args) {
        Predicate<String> notBlank = s -> s != null && !s.isBlank();

        List<String> input = List.of("java", "", "  ", "stream");
        List<String> result = input.stream().filter(notBlank).toList();
        System.out.println(result); // [java, stream]
    }
}
```

```text
// 출력
[java, stream]
```

### B-2. `Function<String, Integer>`로 문자열 길이 변환

"T를 받아 R로 변환"이므로 `Function<String, Integer>`를 사용합니다. 메소드 참조 `String::length`로 더 간결하게 표현할 수 있습니다.

```java
import java.util.function.Function;

public class B2 {
    public static void main(String[] args) {
        Function<String, Integer> length = String::length;
        System.out.println(length.apply("lambda")); // 6
        System.out.println(length.apply(""));       // 0
    }
}
```

```text
// 출력
6
0
```

### B-3. `Consumer<String>`로 로그 출력 함수

```java
        log.accept("요청 처리 완료"); // [LOG] 요청 처리 완료
    }
}
```

```text
// 출력
[LOG] 서버 시작
[LOG] 요청 처리 완료
```

### B-4. `Supplier<UUID>`로 랜덤 ID 생성

"입력 없이 값을 공급"하므로 `Supplier`입니다. 호출할 때마다 새 값이 만들어지는 지연 생성이 특징입니다.

```java
import java.util.UUID;

    }
}
```

```java
}
```

```text
5
```

### C-3. 생성자 참조(`User::new`)로 객체 리스트 생성

`String -> User` 변환 자리에 생성자 참조를 넣으면, 컴파일러가 `User(String)` 생성자에 매핑합니다.

```java
import java.util.List;

class User {
    private final String name;
    User(String name) { this.name = name; }

public class C3 {
    public static void main(String[] args) {

        List<User> users = names.stream()
                .map(User::new) // name -> new User(name)
                .toList();
        System.out.println(users); // [User(kim), User(lee), User(park)]
    }
}
```

```text
// 출력
[User(kim), User(lee), User(park)]
```

## D. 함수 조합

### D-1. trim → lowercase → prefix 추가 조합

`Function.andThen`으로 작은 함수를 이어 붙이면, 각 단계를 독립적으로 테스트/재사용할 수 있습니다.

```java
import java.util.function.Function;

public class D1 {
    public static void main(String[] args) {
        Function<String, String> trim = String::trim;
        Function<String, String> lower = String::toLowerCase;
        Function<String, String> addPrefix = s -> "user:" + s;

        Function<String, String> pipeline = trim.andThen(lower).andThen(addPrefix);

        System.out.println(pipeline.apply("  KimCoding  ")); // user:kimcoding
    }
}
```

```text
// 출력
user:kimcoding
```

### D-2. `Predicate`의 `and`, `or`, `negate` 복합 조건

`Predicate`는 기본 메소드로 논리 조합을 제공하므로, if 문 중첩 대신 조건 자체를 값으로 조립할 수 있습니다.

```java
import java.util.List;
import java.util.function.Predicate;

public class D2 {
    public static void main(String[] args) {
        Predicate<String> notBlank = s -> s != null && !s.isBlank();
        Predicate<String> shortWord = s -> s.length() <= 4;
        Predicate<String> startsWithJ = s -> s.startsWith("j");

        // 비어있지 않고, (4자 이하이거나 j로 시작)
        Predicate<String> filter = notBlank.and(shortWord.or(startsWithJ));

        List<String> words = List.of("java", "  ", "kotlin", "go", "javascript");
        System.out.println(words.stream().filter(filter).toList());
        // [java, go, javascript]

        // negate: 위 조건의 반대
        System.out.println(words.stream().filter(filter.negate()).toList());
        // [  , kotlin]
    }
}
```

```text
// 출력
[java, go, javascript]
[  , kotlin]
```

### D-3. 리스트 전처리 파이프라인을 함수 조합으로 구성

`UnaryOperator<List<String>>`(입출력 타입이 같은 `Function`)을 조합해, "리스트 → 리스트" 전처리 단계를 하나의 파이프라인으로 만듭니다.

```java
import java.util.List;
import java.util.function.Function;
import java.util.function.UnaryOperator;

public class D3 {
    public static void main(String[] args) {
        UnaryOperator<List<String>> removeBlank =
                list -> list.stream().filter(s -> !s.isBlank()).toList();
        UnaryOperator<List<String>> trimAll =
                list -> list.stream().map(String::trim).toList();
        UnaryOperator<List<String>> distinctSorted =
                list -> list.stream().distinct().sorted().toList();

        Function<List<String>, List<String>> preprocess =
                removeBlank.andThen(trimAll).andThen(distinctSorted);

        List<String> raw = List.of(" banana ", "", "apple", " apple", "  ", "cherry");
        System.out.println(preprocess.apply(raw));
        // [apple, banana, cherry]  (" apple"은 trim 후 "apple"과 중복 제거됨)
    }
}
```

```text
// 출력
[apple, banana, cherry]
```

## E. 실무 시나리오

### E-1. 할인 정책을 함수형으로 설계하고 런타임에 교체

정책이 "금액 → 금액" 변환이므로 `UnaryOperator<Integer>`(또는 커스텀 함수형 인터페이스)로 표현하고, 필드 교체만으로 정책을 바꿉니다.

```java
import java.util.function.UnaryOperator;

class PriceCalculator {
    private UnaryOperator<Integer> discountPolicy;

    PriceCalculator(UnaryOperator<Integer> discountPolicy) {
        this.discountPolicy = discountPolicy;
    }
    void changePolicy(UnaryOperator<Integer> policy) { // 런타임 교체
        this.discountPolicy = policy;
    }
    int finalPrice(int price) {
        return discountPolicy.apply(price);
    }
}

public class E1 {
    public static void main(String[] args) {
        UnaryOperator<Integer> tenPercent = price -> price * 90 / 100;
        UnaryOperator<Integer> flat1000 = price -> Math.max(0, price - 1000);

        PriceCalculator calc = new PriceCalculator(tenPercent);
        System.out.println(calc.finalPrice(20000)); // 18000

        calc.changePolicy(flat1000); // 정책 교체
        System.out.println(calc.finalPrice(20000)); // 19000
    }
}
```

```text
// 출력
18000
19000
```

### E-2. 입력 검증 정책을 람다 리스트로 순차 적용

검증 하나하나를 `Predicate`(+ 실패 메시지)로 만들어 리스트에 담으면, 정책 추가/삭제가 리스트 조작으로 끝납니다.

```java
import java.util.List;
import java.util.function.Predicate;

record Rule(String message, Predicate<String> check) {}

public class E2 {
    static List<String> validate(String input, List<Rule> rules) {
        return rules.stream()
                .filter(rule -> !rule.check().test(input))
                .map(Rule::message)
                .toList();
    }

    public static void main(String[] args) {
        List<Rule> rules = List.of(
                new Rule("비어 있으면 안 됩니다", s -> s != null && !s.isBlank()),
                new Rule("8자 이상이어야 합니다", s -> s.length() >= 8),
                new Rule("숫자를 포함해야 합니다", s -> s.chars().anyMatch(Character::isDigit))
        );

        System.out.println(validate("abc", rules));
        // [8자 이상이어야 합니다, 숫자를 포함해야 합니다]
        System.out.println(validate("password1", rules));
        // []  (모든 검증 통과)
    }
}
```

```text
// 출력
[8자 이상이어야 합니다, 숫자를 포함해야 합니다]
[]
```

### E-3. 이벤트 콜백 구조를 람다로 단순화

콜백은 "이벤트 값을 소비"하므로 `Consumer<T>`를 저장해 두었다가 발생 시점에 호출합니다. 리스너용 익명 클래스가 전부 사라집니다.

```java
import java.util.ArrayList;
import java.util.List;
import java.util.function.Consumer;

class Button {
    private final List<Consumer<String>> listeners = new ArrayList<>();
    void onClick(Consumer<String> listener) { listeners.add(listener); }
    void click(String who) { listeners.forEach(l -> l.accept(who)); }
}

public class E3 {
    public static void main(String[] args) {
        Button button = new Button();
        button.onClick(who -> System.out.println(who + " 클릭 로그 저장"));
        button.onClick(who -> System.out.println(who + "에게 화면 갱신 알림"));

        button.click("kim");
        // kim 클릭 로그 저장
        // kim에게 화면 갱신 알림
    }
}
```

```text
// 출력
kim 클릭 로그 저장
kim에게 화면 갱신 알림
```

## F. 챌린지

### F-1. 체크 예외를 다루는 람다 래퍼 유틸

표준 `Function`은 checked 예외를 던질 수 없으므로, `throws Exception`을 허용하는 커스텀 함수형 인터페이스를 만들고, 이를 표준 `Function`으로 감싸는 래퍼 메소드를 제공합니다. 이렇게 하면 스트림 안에서도 checked 예외 API를 쓸 수 있습니다.

```java
import java.util.List;
import java.util.function.Function;

@FunctionalInterface
interface ThrowingFunction<T, R> {
    R apply(T t) throws Exception;
}

class Unchecked {
    // checked 예외를 RuntimeException으로 감싸 표준 Function으로 변환
    static <T, R> Function<T, R> wrap(ThrowingFunction<T, R> f) {
        return t -> {
            try {
                return f.apply(t);
            } catch (RuntimeException e) {
                throw e; // 이미 unchecked면 그대로
            } catch (Exception e) {
                throw new IllegalStateException("람다 실행 실패: " + t, e);
            }
        };
    }
}

public class F1 {
    // checked 예외를 던지는 기존 메소드라고 가정
    static byte[] readBytes(String path) throws java.io.IOException {
        if (path.isBlank()) throw new java.io.IOException("잘못된 경로");
        return path.getBytes(); // 예제 단순화
    }

    public static void main(String[] args) {
        List<String> paths = List.of("a.txt", "b.txt");

        // wrap 덕분에 map에 checked 예외 메소드를 그대로 전달 가능
        List<Integer> sizes = paths.stream()
                .map(Unchecked.wrap(F1::readBytes))
                .map(bytes -> bytes.length)
                .toList();
        System.out.println(sizes); // [5, 5]

        // 예외 발생 케이스: IOException이 IllegalStateException으로 래핑됨
        try {
            List.of("  ").stream().map(Unchecked.wrap(F1::readBytes)).toList();
        } catch (IllegalStateException e) {
            System.out.println(e.getMessage());          // 람다 실행 실패:   
            System.out.println(e.getCause().getClass().getSimpleName()); // IOException
        }
    }
}
```

```text
// 출력
[5, 5]
람다 실행 실패:   
IOException
```

### F-2. 부작용 있는 람다 vs 없는 람다 + 테스트 코드

부작용 없는 람다는 "입력 → 출력"만 검증하면 되므로 테스트가 단순하고, 실행 순서/횟수에 영향을 받지 않습니다. (JUnit 없이 검증하도록 assert 스타일 메소드로 작성)

```java
import java.util.ArrayList;
import java.util.List;

public class F2 {
    // 부작용 있는 버전: 외부 리스트를 변경 (호출 순서, 재실행에 취약)
    static List<Integer> sideEffectVersion(List<Integer> src) {
        List<Integer> out = new ArrayList<>();
        src.forEach(x -> { if (x > 0) out.add(x * 2); }); // 외부 상태 수정
        return out;
    }

    // 부작용 없는 버전: 입력 -> 새 리스트 반환
    static List<Integer> pureVersion(List<Integer> src) {
        return src.stream().filter(x -> x > 0).map(x -> x * 2).toList();
    }

    static void assertEquals(Object expected, Object actual, String name) {
        if (expected.equals(actual)) System.out.println("PASS: " + name);
        else System.out.println("FAIL: " + name + " expected=" + expected + " actual=" + actual);
    }

    public static void main(String[] args) {
        List<Integer> input = List.of(-1, 2, 3);

        // 순수 함수는 같은 입력이면 몇 번을 불러도 같은 결과 (테스트가 쉬움)
        assertEquals(List.of(4, 6), pureVersion(input), "pure 1회차");
        assertEquals(List.of(4, 6), pureVersion(input), "pure 2회차");

        // 부작용 버전도 이 예제에선 결과가 같지만,
        // out을 공유하거나 병렬화하는 순간 결과가 깨질 수 있다.
        assertEquals(List.of(4, 6), sideEffectVersion(input), "sideEffect");
    }
}
```

```text
// 출력
PASS: pure 1회차
PASS: pure 2회차
PASS: sideEffect
```

### F-3. Stream 파이프라인과 결합한 람다 중심 데이터 처리

필터(`Predicate`), 변환(`Function`), 집계까지 모두 람다/메소드 참조로 전달해, "무엇을 할지"만 선언하는 코드를 만듭니다.

```java
import java.util.List;
import java.util.function.Function;
import java.util.function.Predicate;

record Product(String name, String category, int price) {}

public class F3 {
    public static void main(String[] args) {
        List<Product> products = List.of(
                new Product("키보드", "전자", 30000),
                new Product("모니터", "전자", 250000),
                new Product("노트", "문구", 2000),
                new Product("마우스", "전자", 15000)
        );

        Predicate<Product> electronics = p -> p.category().equals("전자");
        Predicate<Product> affordable = p -> p.price() <= 100000;
        Function<Product, String> display = p -> p.name() + "(" + p.price() + "원)";

        List<String> result = products.stream()
                .filter(electronics.and(affordable)) // 조건을 값으로 조합
                .sorted((a, b) -> a.price() - b.price())
                .map(display)
                .toList();
        System.out.println(result); // [마우스(15000원), 키보드(30000원)]

        int total = products.stream()
                .filter(electronics)
                .mapToInt(Product::price)
                .sum();
        System.out.println("전자 총액: " + total); // 전자 총액: 295000
    }
}
```
