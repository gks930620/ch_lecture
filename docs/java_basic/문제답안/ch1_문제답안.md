# ch1 시작하기 — 확인 문제 예시 답안

> 답은 한 가지가 아닙니다. 아래는 예시 답안이며, 스스로 답해 본 뒤에 비교해 보세요.

## 1. JDK, JRE, JVM의 역할

- **JVM**: `.class` 바이트코드를 실제로 실행하는 가상 머신이다.
- **JRE**: JVM + 표준 라이브러리로, 자바 프로그램을 "실행"하는 데 필요한 환경이다.
- **JDK**: JRE + 개발 도구(`javac` 등)로, 자바를 "개발 + 실행"하는 데 필요한 도구 모음이다.

포함 관계: `JDK ⊃ JRE ⊃ JVM`

## 2. `javac HelloWorld.java`의 결과물

`HelloWorld.class` 파일이 만들어진다.
안에는 기계어가 아니라 **바이트코드**(JVM이 이해하는 중간 코드)가 들어있다.
그래서 이 파일은 특정 OS 전용이 아니라, JVM이 있는 곳이면 어디서든 실행할 수 있다.

## 3. WORA(Write Once, Run Anywhere)가 가능한 이유

자바 소스는 OS별 기계어로 바로 컴파일되지 않고 **바이트코드**로 컴파일된다.
바이트코드를 각 OS에 맞게 실행해 주는 것은 그 OS에 설치된 **JVM**의 몫이다.
즉 "코드는 하나(바이트코드), 실행기는 OS마다(JVM)" 구조라서
Windows에서 작성한 프로그램을 Linux 서버에서 재컴파일 없이 실행할 수 있다.

## 4. 개발에 JDK가 필요한 이유

JRE에는 컴파일러 `javac`가 없다.
소스코드(`.java`)를 바이트코드(`.class`)로 바꾸는 **컴파일 단계는 개발 도구가 있어야** 가능하므로,
코드를 작성·컴파일하려면 JDK가 필요하다. (참고: Java 11부터는 JRE 단독 배포가 없어져 실제로는 JDK만 설치한다.)

## 5. 컴파일 오류 vs 실행 중 오류

- **컴파일 오류**: `javac` 단계에서 발견된다. 문법 오류, 타입 오류 등이며, 오류가 있으면 `.class` 파일 자체가 만들어지지 않는다.
- **실행 중 오류**: `java` 단계(JVM 실행 중)에서 발생한다. 0으로 나누기, null 사용 등 실행해 봐야 드러나는 오류다. (자세한 내용은 ch9 예외 처리에서 배운다.)
