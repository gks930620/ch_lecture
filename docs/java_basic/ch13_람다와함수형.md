# ch13_람다와함수형


---



## 학습 목표
- 람다식과 함수형 인터페이스의 관계를 정확히 이해할 수 있다.
- `Predicate`, `Function`, `Consumer`, `Supplier`를 상황별로 사용할 수 있다.
- 부작용을 줄인 함수형 스타일로 가독성과 테스트 용이성을 높일 수 있다.

---

## 1. 람다의 본질

람다는 익명 함수 문법이지만, Java에서는 결국 함수형 인터페이스 구현체다.

```java
Comparator<String> cmp = (a, b) -> a.length() - b.length();
```

람다 이전과 이후를 비교하면 의도가 분명해진다.

```java
// 람다 이전: 익명 클래스
Comparator<String> byLength = new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
};
// 람다: 같은 의미를 한 줄로
Comparator<String> byLength2 = (a, b) -> a.length() - b.length();
```

핵심:
- 동작(behavior)을 값처럼 전달
- 전략을 외부에서 주입
- 보일러플레이트 감소

## 2. 함수형 인터페이스

추상 메소드가 정확히 하나인 인터페이스.

```java
@FunctionalInterface
interface Calculator {
    int calc(int a, int b);
}
```

람다식은 해당 추상 메소드 구현으로 매핑된다.

---

## 3. 표준 함수형 인터페이스

1. `Predicate<T>`: T -> boolean
2. `Function<T, R>`: T -> R
3. `Consumer<T>`: T 소비, 반환 없음
4. `Supplier<T>`: 입력 없이 T 제공
5. `BiFunction<T, U, R>`: (T, U) -> R (인자 2개를 받아 변환)
6. `UnaryOperator<T>`: `Function<T, T>`의 특수형 (입력과 출력 타입이 같음)
7. `BinaryOperator<T>`: 인자 2개를 받는 `BiFunction<T, T, T>`의 특수형 (예: `(a, b) -> a + b`)

예:

```java
Predicate<String> notBlank = s -> s != null && !s.isBlank(); // isBlank(): 비어있거나 공백뿐이면 true (Java 11+)
Function<String, Integer> length = String::length;
Consumer<String> out = System.out::println;
Supplier<UUID> uuid = UUID::randomUUID; // UUID: 랜덤 고유 식별자를 만들어 주는 클래스
```

> 실습 소스: `src/P4표준함수형인터페이스/표준함수형Main.java` (함수 조합은 `src/P5함수조합/함수조합Main.java`)

## 4. 람다 문법 포인트

```java
(파라미터) -> 표현식
(파라미터) -> { 문장; return 값; }
```

규칙:
- 파라미터 타입은 대부분 추론 가능
- 파라미터 1개면 괄호 생략 가능
- 본문이 1식이면 중괄호/return 생략 가능

## 5. 메소드 참조

람다를 더 간결하게 표현하는 문법.

종류:
1. `ClassName::staticMethod`
2. `instance::instanceMethod`
3. `ClassName::instanceMethod`
4. `ClassName::new` (생성자 참조)

종류별로 람다와 메소드 참조를 대응시켜 보면 다음과 같다.

```java
Function<String, Integer> f1 = Integer::parseInt;      // 1. static: s -> Integer.parseInt(s)
Supplier<List<String>> f2 = ArrayList::new;             // 4. 생성자: () -> new ArrayList<>()
Function<String, Integer> f3 = String::length;          // 3. 임의 객체의 인스턴스 메소드: s -> s.length()
String prefix = "Hello";
Predicate<String> f4 = prefix::startsWith;              // 2. 특정 객체의 인스턴스 메소드: s -> prefix.startsWith(s)
```

특히 3번(`ClassName::instanceMethod`)은 첫 번째 매개변수가 호출 대상(수신 객체)이 된다는 점에 주의하자.

## 6. 함수 조합(Composition)

`Function`은 조합 메소드를 제공한다.

```java
Function<String, String> trim = String::trim;
Function<String, String> lower = String::toLowerCase;
Function<String, String> normalize = trim.andThen(lower);

System.out.println(normalize.apply(" Hello ")); // "hello"
```

![함수 조합 파이프라인]({{ '/java_basic/java_basic_images/ch13/function-composition.svg' | relative_url }})

- `f.andThen(g)`: f 먼저, 그다음 g — 데이터가 왼쪽에서 오른쪽으로 흐른다
- `g.compose(f)`: 결과는 같지만 "g(f(x))"처럼 수학식 순서로 읽는 방식

작은 함수들을 조합하면 재사용성과 테스트 용이성이 높아진다.

## 7. 부작용과 불변성

함수형 스타일 핵심은 "부작용 최소화"다.

지양:
- 람다 내부에서 외부 가변 상태 수정
- 전역 상태 누적

권장:
- 입력 -> 출력 변환 중심
- 불변 데이터 구조와 조합

대안:

2. 예외 래핑 유틸 함수
3. checked를 runtime으로 의미 있게 변환

## 11. 정리

- 람다는 문법 단축이 아니라 동작 전달 모델이다.
- 함수형 인터페이스와 함수 조합을 이해하면 코드 유연성이 크게 올라간다.
- 부작용을 줄이는 방향으로 쓰는 것이 함수형 스타일의 핵심이다.
