# ch12_컬렉션


---



## 학습 목표
- Java 컬렉션 계층(List/Set/Map)의 목적과 차이를 이해할 수 있다.
- 상황별 구현체 선택 기준(성능/중복/순서/정렬)을 설명할 수 있다.
- `equals/hashCode`, 정렬, 반복자, 동시성 이슈를 실무 관점으로 다룰 수 있다.

---

## 1. 컬렉션이 필요한 이유

배열은 고정 길이에 제공 기능이 제한적이다.  
컬렉션은 가변 크기 + 풍부한 연산 + 표준 API를 제공한다.

핵심 인터페이스:
- `List`
- `Set`
- `Map`

![컬렉션 선택 지도]({{ '/java_basic/java_basic_images/ch12/collection-selection-map.svg' | relative_url }})

---

## 2. List

특성:
- 순서 보장
- 중복 허용
- 인덱스 접근 가능

대표 구현:
1. `ArrayList`: 조회 빠름, 중간 삽입/삭제 느림
2. `LinkedList`: 중간 삽입/삭제가 이론상 유리하지만, 삽입 위치까지 탐색하는 비용 때문에 실무 기본값은 `ArrayList`다. `LinkedList`는 양끝 삽입/삭제(Deque 용도)에 적합

![ArrayList vs LinkedList 내부 구조]({{ '/java_basic/java_basic_images/ch12/arraylist-vs-linkedlist.svg' | relative_url }})

---

## 3. Set

특성:
- 중복 불가
- 순서 보장 여부는 구현체마다 다름

대표 구현:
1. `HashSet`: 해시 기반, 일반적으로 빠름
2. `LinkedHashSet`: 입력 순서 유지
3. `TreeSet`: 정렬 상태 유지(log n)

---

## 4. Map

특성:
- key-value 쌍
- 키 중복 불가, 값 중복 가능

대표 구현:
1. `HashMap`: 일반적으로 빠른 키 조회
2. `LinkedHashMap`: 삽입 순서 유지. 생성자 세 번째 인자로 `accessOrder=true`를 주면(`new LinkedHashMap<>(16, 0.75f, true)`) 접근 순서 모드가 되어 LRU 캐시 구현에 활용된다(LRU: 가장 오래 사용하지 않은 항목부터 제거하는 캐시 정책, Least Recently Used). 기본값인 삽입 순서 모드로는 LRU를 만들 수 없다는 점에 주의
3. `TreeMap`: 키 정렬 유지

---

## 5. 성능 관점 기초

일반적인 평균 복잡도:
- `ArrayList` 조회: O(1), 중간 삽입: O(n)
- `HashSet`/`HashMap` 탐색: O(1) 평균
- `TreeSet`/`TreeMap` 탐색: O(log n)

주의:
- 해시 충돌, 리사이징, 데이터 분포에 따라 실제 성능은 달라질 수 있다.

---

## 6. equals/hashCode 계약 (매우 중요)

`Set`/`Map` 키에서 객체 동등성은 `equals/hashCode` 계약에 의존한다.

![HashMap/HashSet의 2단계 조회 — hashCode로 버킷, equals로 확정]({{ '/java_basic/java_basic_images/ch12/hash-lookup-flow.svg' | relative_url }})

규칙:
1. `equals`가 true면 `hashCode`도 동일해야 함
2. 객체 상태가 변해 `hashCode`가 바뀌면 컬렉션 동작이 깨질 수 있음

값 객체를 키로 쓸 때는 불변 설계가 유리하다.

Java 16+의 `record`를 쓰면 `equals/hashCode`를 자동으로 제공받는다.

```java
record User(Long id, String name) { } // equals/hashCode 자동 생성
```

일반 클래스에서 직접 재정의할 때는 ch6의 `Objects.equals`/`Objects.hash` 예제를 참고하자.

---

## 7. 반복과 수정

`for-each` 순회 중 구조 변경 시 `ConcurrentModificationException`이 발생할 수 있다.

안전한 삭제:

```java
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().isBlank()) it.remove();
}
```

## 8. 정렬

### 8.1 자연 정렬 `Comparable`

객체 내부에 기본 정렬 기준을 정의.

```java
class User implements Comparable<User> {
    private final String name;
    private final int age;

    User(String name, int age) { this.name = name; this.age = age; }

    public String getName() { return name; }
    public int getAge() { return age; }

    @Override
    public int compareTo(User other) {
        return Integer.compare(this.age, other.age); // 나이 오름차순
    }
}
```

### 8.2 사용자 정의 정렬 `Comparator`

상황별 정렬 전략을 외부에서 주입.

```java
list.sort(Comparator.comparing(User::getAge).thenComparing(User::getName));
```

## 9. 불변 컬렉션

```java
List<String> fixed = List.of("A", "B");
```

특징:
- 구조 변경 불가 — `add`/`remove` 호출 시 `UnsupportedOperationException` 발생
- 읽기 전용 데이터 전달에 적합

---

## 10. 동시성 컬렉션

멀티스레드는 ch16에서 배운다. 여기서는 "이런 컬렉션이 있다"는 것만 알아두자.

멀티스레드 환경에서 일반 컬렉션은 안전하지 않다.

대안:
- `ConcurrentHashMap`
- `CopyOnWriteArrayList`
- `Collections.synchronizedList(...)` (상황에 따라)

동시성 패턴에 맞는 컬렉션 선택이 필요하다.

---

## 11. 실무 선택 가이드

1. 기본 목록: `ArrayList`
2. 중복 제거: `HashSet`
3. 키 조회: `HashMap`
4. 정렬 상태 유지 필요: `TreeMap`/`TreeSet`
5. 순서 보존 + 키 조회: `LinkedHashMap`

---

## 12. 정리

- 컬렉션 선택은 습관이 아니라 요구사항 기반 의사결정이다.
- 중복, 순서, 정렬, 조회 패턴, 동시성 요구를 함께 고려해야 한다.
- `equals/hashCode`와 정렬 기준이 컬렉션 안정성을 좌우한다.
