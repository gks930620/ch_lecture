# 협업 방식 정리

1. 협업은 **기능별로** 나눈다. (게시글 담당, 댓글 담당, 파일 담당 ...)
2. 하나의 기능을 만들 때 아무렇게나 만들지 말고 **서로 협의해서** 만든다.
   - URL 설계, 요청/응답 형태, 예외 처리 방식 등을 미리 맞춰야 나중에 합칠 때 문제가 없다.
   - 참고: 실무 스프링 프로젝트는 CSR(REST API) 방식으로 역할 분담이 잘 정립되어 있는 경우가 많다.
   - 공통 UTIL이나 공통 기능(로그인, AOP, 예외 처리 등)은 상급자가 먼저 잘 만들어 두고, 팀원들은 그것을 가져다 쓴다.
3. 기능별로 branch를 따서 **PR 받고 merge** 한다. (협의한 내용에 맞게 잘 되었는지 리뷰로 확인)
4. CSR 방식이면 SWAGGER 등으로 **API 문서화**를 해서 프론트엔드와의 협업까지 이어진다.
