# ch12_트랜잭션

---

## 학습 목표
- 트랜잭션이 무엇이고 왜 필요한지 계좌이체 예시로 설명할 수 있다.
- COMMIT / ROLLBACK / SAVEPOINT 를 쓸 수 있다.
- 잠금(lock) 때문에 다른 세션이 멈추는 현상을 이해한다.
- 자동 커밋 여부 등 실무 주의사항을 안다.

ch3 에서 "DML 후엔 COMMIT" 만 익혔다. 이번엔 전체 그림이다.

---

## 1. 트랜잭션이란 — 전부 되거나, 전부 안 되거나

**트랜잭션(transaction) = 하나의 업무를 이루는 SQL 묶음.** 쪼개지면 안 되는 최소 작업 단위다.

대표 예시, 계좌이체. "A 가 B 에게 10만 원 이체"는 SQL 두 개다.

```sql
UPDATE ACCOUNT SET BALANCE = BALANCE - 100000 WHERE OWNER = 'A';  -- A 출금
UPDATE ACCOUNT SET BALANCE = BALANCE + 100000 WHERE OWNER = 'B';  -- B 입금
```

> `ACCOUNT` 는 개념 설명용 가상 테이블이다. 실습테이블에는 없으니 실행하지 말고 눈으로만 따라오면 된다.

만약 첫 UPDATE 만 실행되고 정전이 났다면? A 돈만 사라졌다. 있어서는 안 되는 상태다.  
트랜잭션은 이 두 문장을 하나로 묶어서 보장한다:

- 둘 다 성공 → `COMMIT` → 두 변경이 **동시에** 확정
- 하나라도 실패 → `ROLLBACK` → **둘 다 없던 일로**

중간 상태는 존재하지 않는다. 이것이 트랜잭션의 핵심 성질(원자성)이다.

> 참고 — 트랜잭션의 4대 성질 **ACID**:  
> **A**tomicity(원자성, 전부 아니면 전무) / **C**onsistency(일관성, 규칙 위반 상태로 못 끝남) /  
> **I**solation(고립성, 동시에 실행돼도 서로 안 섞임) / **D**urability(지속성, COMMIT 되면 장애에도 안 사라짐).  
> 면접 단골. 지금은 A 와 I 를 몸으로 이해하는 것이 목표다.

## 2. 트랜잭션의 시작과 끝

오라클은 `BEGIN TRANSACTION` 같은 시작 선언이 없다.

- **시작**: 첫 DML(INSERT/UPDATE/DELETE)을 실행하는 순간 자동 시작
- **끝**: `COMMIT`(확정) 또는 `ROLLBACK`(취소). 끝나면 다음 DML 에서 새 트랜잭션이 시작된다.

트랜잭션이 저절로 끝나 버리는 경우도 있다:

| 상황 | 처리 |
|------|------|
| DDL 실행 (CREATE, DROP, ALTER, TRUNCATE) | **자동 COMMIT** (직전 DML 까지 같이 확정된다!) |
| 정상 접속 종료 (SQL*Plus 의 exit) | 자동 COMMIT (도구 설정에 따라 다름) |
| 비정상 종료 (강제 종료, 정전) | 자동 ROLLBACK |

> 학생들이 쓰는 SQL Developer 는 미커밋 변경이 있는 채로 접속/프로그램을 닫으려 하면 **커밋할지 롤백할지 물어본다.** SQL*Plus 처럼 조용히 자동 커밋되지 않으니, 창을 닫을 때 뜨는 물음에 잘 답하자.

"DDL 은 자동 COMMIT" 이 특히 함정이다. DELETE 해 놓고 ROLLBACK 으로 되돌릴 생각이었는데,  
그 사이에 CREATE TABLE 하나 실행했다면 DELETE 까지 이미 확정돼 버린 것이다.

## 3. SAVEPOINT — 부분 되돌리기

트랜잭션 중간에 **책갈피**를 꽂아 두고, 거기까지만 되돌릴 수 있다.

```sql
INSERT INTO DEPT VALUES (50, '총무팀', '대전');

SAVEPOINT SP1;                                   -- 책갈피 1

UPDATE EMP SET SALARY = SALARY + 100 WHERE DEPT_ID = 10;

SAVEPOINT SP2;                                   -- 책갈피 2

DELETE FROM ORDERS;                              -- 아차, 실수!

ROLLBACK TO SP2;    -- DELETE 만 취소. INSERT/UPDATE 는 살아 있다
ROLLBACK TO SP1;    -- UPDATE 도 취소. INSERT 는 살아 있다
COMMIT;             -- 남은 것(INSERT) 확정
```

- `ROLLBACK TO 세이브포인트` 는 트랜잭션을 끝내지 않는다. 계속 이어서 작업할 수 있다.
- 그냥 `ROLLBACK` 은 전부 취소하고 트랜잭션을 끝낸다.

## 4. 잠금(Lock) — 동시에 고치면 어떻게 되나

같은 데이터를 두 사람이 동시에 수정하면? 오라클은 **행 단위 잠금**으로 교통정리한다.

두 개의 SQL Developer 접속(세션)으로 직접 실험해 보자.

```
세션 A                                        세션 B
─────────────────────────────────────         ─────────────────────────────────────
UPDATE EMP SET SALARY = 5000
WHERE EMP_ID = 1003;   (커밋 안 함)
                                              UPDATE EMP SET SALARY = 6000
                                              WHERE EMP_ID = 1003;
                                              → 멈춰서 하염없이 기다린다...
COMMIT;
                                              → 그제서야 실행된다
```

- 세션 A 가 1003번 행을 수정하는 순간, 그 **행**에 잠금이 걸린다.
- 세션 B 는 같은 행을 수정하려면 A 가 COMMIT/ROLLBACK 할 때까지 **대기**한다.
- 다른 행(1004번)을 수정하는 것은 안 막힌다. (행 단위이므로)

실무에서 "쿼리가 안 끝나고 무한 대기해요"의 흔한 원인: **누군가 커밋 안 하고 퇴근**. 트랜잭션은 필요한 만큼만 짧게 유지하고 바로 COMMIT 하자.

### 4.1 읽기는 안 막힌다 — 읽기 일관성

세션 A 가 커밋 전일 때, 세션 B 가 그 행을 **SELECT** 하면?

- 기다리지 않는다. **변경 전의 값**이 조회된다.
- 오라클은 커밋 안 된 남의 변경을 절대 보여주지 않는다 (읽기 일관성, UNDO 데이터 활용).

그래서: 읽기끼리는 안 막히고, 읽기와 쓰기도 안 막히고, **쓰기와 쓰기만 (같은 행일 때) 막힌다.**

---

## 5. 실무 주의사항

- **자동 커밋 설정 확인**: SQL*Plus 의 `SET AUTOCOMMIT ON`, 일부 도구/드라이버(JDBC 기본값!)는 문장마다 자동 COMMIT 한다.  
  Java(JDBC/Spring)에서 트랜잭션을 묶으려면 자동 커밋을 끄고 명시적으로 관리한다 — Spring 의 `@Transactional` 이 바로 이 일을 해 준다.
- **트랜잭션은 짧게**: 잠금을 오래 쥐고 있으면 다른 사용자가 다 기다린다. "UPDATE 해 놓고 점심 먹으러 가기" 금지.
- **확정 전 확인**: 중요한 UPDATE/DELETE 는 COMMIT 전에 SELECT 로 결과를 확인하고, 이상하면 ROLLBACK.
- 여러 테이블을 갱신하는 업무(주문 생성 = 주문 INSERT + 재고 UPDATE)는 **반드시 한 트랜잭션**으로 묶는다.

---

## 정리

- 트랜잭션 = 쪼개지면 안 되는 SQL 묶음. 전부 확정(COMMIT) 아니면 전부 취소(ROLLBACK).
- 오라클은 첫 DML 에서 자동 시작, COMMIT/ROLLBACK 으로 끝. **DDL 은 자동 COMMIT** 이라는 함정 주의.
- SAVEPOINT 로 중간 지점까지 부분 취소 가능.
- 수정 중인 행은 잠긴다: 쓰기끼리만 막히고, 읽기는 변경 전 값을 본다(읽기 일관성).
- 트랜잭션은 짧게, DML 후엔 반드시 COMMIT/ROLLBACK 으로 마무리.

1. 계좌이체가 UPDATE 두 번으로 이루어질 때, 트랜잭션 없이 실행하면 생길 수 있는 문제와 트랜잭션이 그것을 어떻게 막는지 설명하시오.
2. 다음을 순서대로 실행했다. 최종적으로 DB 에 남는 변경은 무엇인가?
   ```sql
   INSERT INTO DEPT VALUES (60, '법무팀', '서울');
   SAVEPOINT A;
   UPDATE EMP SET BONUS = 999 WHERE EMP_ID = 1001;
   SAVEPOINT B;
   DELETE FROM ORDERS WHERE ORDER_ID = 5001;
   ROLLBACK TO A;
   COMMIT;
   ```
3. 다음을 순서대로 실행했다. ROLLBACK 후 ORDERS 의 5002번 주문은 살아 있는가? 이유는?
   ```sql
   DELETE FROM ORDERS WHERE ORDER_ID = 5002;
   CREATE TABLE TEMP1 (A NUMBER);
   ROLLBACK;
   ```
4. 세션 A 가 `UPDATE EMP SET SALARY=9999 WHERE EMP_ID=1005;` 를 실행하고 커밋하지 않았다.
   - (a) 세션 B 가 같은 행을 UPDATE 하면 어떻게 되는가?
   - (b) 세션 B 가 같은 행을 SELECT 하면 월급이 얼마로 보이는가?
5. (실습) SQL Developer 접속을 2개 열어 4번 상황을 직접 재현해 보시오. 세션 A 에서 COMMIT 하는 순간 세션 B 에서 무슨 일이 일어나는지 관찰하시오.
