# ch11_윈도우함수

---

## 학습 목표
- 윈도우 함수가 그룹 함수와 어떻게 다른지 안다.
- RANK / DENSE_RANK / ROW_NUMBER 로 순위를 매길 수 있다.
- PARTITION BY 로 그룹별 순위/집계를 낼 수 있다.
- SUM OVER 누적합, LAG/LEAD 를 쓸 수 있다.
- ROWNUM 과 FETCH FIRST 로 TOP-N 쿼리를 작성할 수 있다.

---

## 1. 윈도우 함수란 — 행을 줄이지 않는 집계

ch6 의 그룹 함수는 여러 행을 **1행으로 접었다.**  
그런데 "각 사원 옆에 **전체 평균 월급**을 나란히 보여줘" 는 어떻게 할까? 행은 12개 그대로 있어야 한다.

```sql
SELECT EMP_NAME,
       SALARY,
       ROUND(AVG(SALARY) OVER ()) AS 전체평균
FROM   EMP;
```

| EMP_NAME | SALARY | 전체평균 |
|----------|--------|---------|
| 김철수 | 9000 | 4675 |
| 이영희 | 6500 | 4675 |
| ... (12행 전부) | | |

`OVER ()` 가 붙으면 윈도우 함수다. **행을 접지 않고**, 각 행 옆에 집계 결과를 붙여 준다.

```
그룹 함수  : 12행 → 1행 (접는다)
윈도우 함수: 12행 → 12행 (옆에 붙인다)
```

`OVER (...)` 괄호 안에 "어느 범위(window)를 보고 계산할지"를 적는다.

- `OVER ()` — 전체
- `OVER (PARTITION BY 컬럼)` — 같은 값끼리 나눈 그룹 안에서
- `OVER (ORDER BY 컬럼)` — 정렬해서 누적으로

## 2. 순위 함수 — RANK, DENSE_RANK, ROW_NUMBER

```sql
SELECT EMP_NAME,
       SALARY,
       RANK()       OVER (ORDER BY SALARY DESC) AS RANK순위,
       DENSE_RANK() OVER (ORDER BY SALARY DESC) AS DENSE순위,
       ROW_NUMBER() OVER (ORDER BY SALARY DESC) AS 행번호
FROM   EMP;
```

셋의 차이는 **동점 처리**다. 만약 월급 5000 이 두 명이라면:

| SALARY | RANK | DENSE_RANK | ROW_NUMBER |
|--------|------|------------|------------|
| 6000 | 1 | 1 | 1 |
| 5000 | 2 | 2 | 2 |
| 5000 | 2 | 2 | 3 |
| 4000 | **4** | **3** | 4 |

- `RANK` — 공동 2등이 2명이면 다음은 4등 (올림픽식)
- `DENSE_RANK` — 공동 2등 다음은 3등 (건너뛰지 않음)
- `ROW_NUMBER` — 동점이어도 무조건 1, 2, 3, … (유일한 번호)

### 2.1 PARTITION BY — 그룹별 순위

"**부서별로** 월급 순위" — 부서마다 1등부터 다시 센다.

```sql
SELECT DEPT_ID,
       EMP_NAME,
       SALARY,
       RANK() OVER (PARTITION BY DEPT_ID ORDER BY SALARY DESC) AS 부서내순위
FROM   EMP;
```

PARTITION BY 는 "칸막이"다. GROUP BY 처럼 행을 접지 않고, 칸막이 안에서만 순위/집계를 계산한다.

### 2.2 부서별 1등만 뽑기 (실무 단골 패턴)

윈도우 함수는 WHERE 에 바로 못 쓴다 (WHERE 가 SELECT 보다 먼저 실행되므로).  
**인라인 뷰(ch8)로 감싸서** 거른다.

```sql
SELECT DEPT_ID, EMP_NAME, SALARY
FROM   (SELECT DEPT_ID, EMP_NAME, SALARY,
               ROW_NUMBER() OVER (PARTITION BY DEPT_ID ORDER BY SALARY DESC) AS RN
        FROM   EMP)
WHERE  RN = 1;
```

"그룹별 최신 1건", "카테고리별 베스트 상품" 등 실무에서 정말 자주 쓴다.

## 3. 집계 윈도우 — 누적합, 그룹별 집계 붙이기

```sql
-- 입사일 순서대로 월급 누적합
SELECT EMP_NAME,
       HIRE_DATE,
       SALARY,
       SUM(SALARY) OVER (ORDER BY HIRE_DATE) AS 누적합
FROM   EMP;
```

`ORDER BY` 가 들어간 SUM 은 "처음부터 현재 행까지"의 누적 합계가 된다. (월별 누적 매출 그래프가 이 패턴)

```sql
-- 각 사원 옆에 소속 부서의 평균월급을 붙이고, 평균과의 차이 계산
SELECT EMP_NAME,
       DEPT_ID,
       SALARY,
       ROUND(AVG(SALARY) OVER (PARTITION BY DEPT_ID)) AS 부서평균,
       SALARY - ROUND(AVG(SALARY) OVER (PARTITION BY DEPT_ID)) AS 평균과의차이
FROM   EMP;
```

ch8 에서 서브쿼리로 풀던 것을 한 번의 조회로 해결한다.

## 4. LAG / LEAD — 앞 행, 뒤 행 값 가져오기

```sql
SELECT EMP_NAME,
       HIRE_DATE,
       SALARY,
       LAG(SALARY)  OVER (ORDER BY HIRE_DATE) AS 직전입사자월급,
       LEAD(SALARY) OVER (ORDER BY HIRE_DATE) AS 다음입사자월급
FROM   EMP;
```

- `LAG` = 정렬 기준으로 **이전 행**의 값(첫 행은 이전이 없어 NULL), `LEAD` = **다음 행**의 값(마지막 행은 다음이 없어 NULL).
- `LAG(SALARY, 2, 0)` — 2행 전 값, 없으면 0.

전월 대비 증감 계산이 대표 용도다:

```sql
-- 월별 주문수량과 전월 대비 증감
SELECT TO_CHAR(ORDER_DATE, 'YYYY-MM') AS 월,
       SUM(QUANTITY) AS 수량,
       SUM(QUANTITY) - LAG(SUM(QUANTITY)) OVER (ORDER BY TO_CHAR(ORDER_DATE, 'YYYY-MM')) AS 전월대비
FROM   ORDERS
GROUP BY TO_CHAR(ORDER_DATE, 'YYYY-MM')
ORDER BY 월;
```

(GROUP BY 로 먼저 월별 집계를 만들고, 그 결과 위에서 윈도우 함수가 동작한다)

## 5. TOP-N 쿼리 — 상위 N건만 조회

### 5.1 ROWNUM (오라클 전통 방식)

`ROWNUM` 은 조회 결과 행에 1부터 붙는 가상 번호다.

```sql
SELECT ROWNUM, EMP_NAME, SALARY FROM EMP;
```

**함정**: ROWNUM 은 **정렬 전에** 붙는다. 그래서 이렇게 쓰면 틀린다.

```sql
-- 월급 TOP 3 을 의도했지만 틀린 쿼리!
SELECT * FROM EMP
WHERE  ROWNUM <= 3
ORDER BY SALARY DESC;
-- "아무 순서로 먼저 잡힌 3명"을 뽑은 뒤에 그 3명을 정렬한 것
```

올바른 방법: **먼저 정렬(인라인 뷰) → 그 다음 ROWNUM**.

```sql
SELECT ROWNUM, T.*
FROM   (SELECT EMP_NAME, SALARY
        FROM   EMP
        ORDER BY SALARY DESC) T
WHERE  ROWNUM <= 3;
```

> 또 하나의 함정: `WHERE ROWNUM = 2` 나 `ROWNUM > 1` 은 항상 0건이다.  
> ROWNUM 은 행이 채택될 때 1부터 차례로 붙기 때문에, 1을 건너뛰고 2부터 시작할 수 없다.

### 5.2 FETCH FIRST (12c 이상, 권장)

```sql
-- 월급 TOP 3
SELECT EMP_NAME, SALARY
FROM   EMP
ORDER BY SALARY DESC
FETCH FIRST 3 ROWS ONLY;

-- 페이징: 4번째부터 3건 (게시판 2페이지)
SELECT EMP_NAME, SALARY
FROM   EMP
ORDER BY SALARY DESC
OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY;
```

정렬 후에 자르는 것이 문법에 내장되어 있어 직관적이다. 12c 이상이면 이걸 쓰자.  
(옛 코드와 옛 오라클 버전 때문에 ROWNUM 방식도 반드시 읽을 줄 알아야 한다)

## 정리

- 윈도우 함수 = `함수() OVER (...)`. 행을 접지 않고 각 행 옆에 집계/순위를 붙인다.
- 순위: RANK(동점 다음 건너뜀) / DENSE_RANK(안 건너뜀) / ROW_NUMBER(무조건 유일). 그룹별은 `PARTITION BY`.
- "그룹별 1등" = ROW_NUMBER + 인라인 뷰 + `WHERE RN = 1`.
- `SUM() OVER (ORDER BY ...)` 는 누적합, LAG/LEAD 는 이전/다음 행 값.
- TOP-N: 12c 이상은 `ORDER BY ... FETCH FIRST N ROWS ONLY`. ROWNUM 은 반드시 "정렬 → 인라인 뷰 → ROWNUM" 순서로.

## 문제

실습테이블 기준.

1. 사원 이름, 월급, 월급 순위(RANK, 전체 기준 내림차순)를 조회하시오.
2. 부서별로 입사일이 빠른 순서대로 번호(ROW_NUMBER)를 붙여, 부서번호/이름/입사일/번호를 조회하시오.
3. 각 부서에서 월급이 가장 높은 사원 1명씩만 조회하시오. (2.2 패턴)
4. 주문일 순서대로 주문금액(가격×수량)의 누적합을 조회하시오. (ORDERS 와 PRODUCT 를 조인한 후 SUM OVER)
5. 입사일 순으로 정렬했을 때, 각 사원의 월급이 직전 입사자 월급보다 얼마나 차이 나는지(현재 - 직전) 조회하시오.
6. 월급이 가장 높은 사원 5명을 FETCH FIRST 로 조회하시오. 같은 결과를 ROWNUM 방식으로도 작성하시오.
7. (생각해보기) 문제 1에서 RANK 대신 DENSE_RANK, ROW_NUMBER 를 쓰면 현재 데이터에서 결과가 달라지는가? 달라진다면/안 달라진다면 왜인가?
