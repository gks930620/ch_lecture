# ch10 문제답안

[← ch10 문서로](../ch10_시퀀스인덱스뷰.md)

## 1. 시퀀스 생성

```sql
CREATE SEQUENCE SEQ_ORDERS
    START WITH 1000
    INCREMENT BY 1;
```

## 2. 시퀀스로 주문 INSERT

```sql
INSERT INTO ORDERS (ORDER_ID, PRODUCT_ID, EMP_ID, CUSTOMER_NAME, QUANTITY, ORDER_DATE)
VALUES (SEQ_ORDERS.NEXTVAL, 2006, 1008, '한소희', 2, SYSDATE);

COMMIT;
```

`SEQ_ORDERS.NEXTVAL` 이 1000을 돌려주므로 주문번호 1000으로 들어간다. (기존 주문번호 5001~5010 과 겹치지 않는다)

## 3. 인덱스 생성

```sql
CREATE INDEX IDX_ORDERS_CUSTOMER ON ORDERS (CUSTOMER_NAME);
```

`WHERE CUSTOMER_NAME = '나민호'` 처럼 **고객 이름으로 주문을 검색하는 쿼리**가 빨라진다.  
데이터 10건에서는 체감이 안 되지만, 주문이 수백만 건이면 전체를 읽는 대신 인덱스로 바로 찾아간다.

## 4. 인덱스를 탈 수 있는 LIKE

- (a) `LIKE '나%'` — **인덱스 사용 가능.** 인덱스는 정렬되어 있으므로 '나' 로 시작하는 구간만 골라 읽을 수 있다.
- (b) `LIKE '%호'` — **사용 불가.** 시작 부분을 모르면 정렬의 이점을 쓸 수 없어 결국 전체를 훑는다.

## 5. 주문 상세 뷰 + 고객별 합계

```sql
CREATE OR REPLACE VIEW V_ORDER_DETAIL AS
SELECT O.ORDER_ID,
       P.PRODUCT_NAME,
       E.EMP_NAME             AS 담당사원,
       O.CUSTOMER_NAME,
       P.PRICE * O.QUANTITY   AS 주문금액
FROM   ORDERS O
JOIN   PRODUCT P ON O.PRODUCT_ID = P.PRODUCT_ID
LEFT JOIN EMP E  ON O.EMP_ID     = E.EMP_ID;

-- 뷰를 테이블처럼 사용
SELECT CUSTOMER_NAME,
       SUM(주문금액) AS 총주문금액
FROM   V_ORDER_DETAIL
GROUP BY CUSTOMER_NAME
ORDER BY 총주문금액 DESC;
```

초기 데이터(주문 10건) 기준 결과:

| CUSTOMER_NAME | 총주문금액 |
|---------------|-----------|
| 장서준 | 3,400,000 |
| 고윤아 | 2,650,000 |
| 나민호 | 2,090,000 |
| 문세윤 | 1,780,000 |

(2번 문제의 한소희 주문을 COMMIT 했다면 한소희 60,000 이 추가된다)

## 6. ROLLBACK 과 시퀀스 번호

꺼낸 번호는 ROLLBACK 해도 반납되지 않는다. 다음 INSERT 는 **그 다음 번호**를 받는다. (1000을 꺼낸 INSERT 를 ROLLBACK 했어도 다음은 1001)

문제가 되지 않는 이유: 기본키에 필요한 성질은 **유일성**(안 겹치는 것)이지 연속성이 아니다.  
게시글 번호가 1, 2, 4 로 건너뛰어도 아무 기능도 고장 나지 않는다. 오히려 번호를 반납받으려고 하면 동시성이 깨져서 시퀀스의 존재 이유가 사라진다.
