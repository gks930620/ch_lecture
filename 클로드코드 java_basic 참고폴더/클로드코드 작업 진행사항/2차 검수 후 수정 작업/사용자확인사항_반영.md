## 1. [보안] ch15 DB 접속정보 → 명확한 예시 플레이스홀더로 교체

**지시:** 실제값처럼 보이는 값 대신 "DB url / DB 유저ID" 같은 명확한 예시값으로.

2차에서 `nextit.or.kr`/`std225`/`oracle21c`(실제값)을 `localhost`/`student`/`password1234`로 바꿨으나,
이 역시 "실제값처럼" 보이므로 한눈에 예시임을 알 수 있는 플레이스홀더로 재교체.

- `"jdbc:oracle:thin:@localhost:1521:xe","student","password1234"`
  → `"jdbc:oracle:thin:@DB주소:1521:xe","DB유저ID","DB비밀번호"`
- 주석도 `(호스트/계정/비밀번호는…)` → `(DB주소·유저ID·비밀번호는 본인 환경에 맞게 변경)`
- **대상:** `P2JDBC기본` 7파일(JDBC기본1, 기본2Select/Insert/SelectWhere/SelectWhere2Pstmt/매핑/매핑DTO/매핑DTO2) + `DAO/MemberDAO` 5곳
- `P1JDBC개요/JDBC개요메인2`는 이미 `"주소","userId","password"` 플레이스홀더라 그대로 둠.
- 문서(`ch15_JDBC.md`)·quest는 이미 `url,user,password` 변수형이라 무변경.
- **재스캔 결과:** `nextit|std225|oracle21c|jdbc:oracle:thin:@localhost` 잔존 0건. 남은 것은 `010-0000-0000`(전부 0)·"예시 아파트" 등 가상 데이터뿐.

> ⚠️ (2차와 동일) git 과거 커밋 이력의 실접속정보·DB 비밀번호 변경은 파일 수정만으로 해결 안 됨 — 사용자가 git은 신경쓰지 않기로 하여 **이력 정리는 패스**.

## 3. [일치] ch7 문서-소스 Animal/Dog 체계로 통일

**지시:** Animal/Dog가 더 좋은 예제. 소스도 거기 맞춰 일치, 실습예제도 정확히.

문서 ch7은 Animal/Dog/Cat/Bird/Shape로 일관됐으나 소스는 Book/Idol/Pet 등 혼재 → 소스를 Animal 도메인으로 재작성.

- **P1상속기본:** Book/ChildrenBook/HorrorBook → `Animal`(name,age,sound,info) + `Dog`(fetch)/`Cat`(scratch). 상속·오버라이딩.
- **P2타입변환:** Animal/Cat만 있던 것에 `Dog` 추가, `sound()` 기준으로 통일. 업캐스팅/다운캐스팅 + `instanceof` 패턴 매칭 + ClassCastException 데모(문서와 일치).
- **P3다형성:** Idol(Ive/Newjeans/Fan)·driver(Vehicle/Car/Autobike/Driver) → `Animal`/`Dog`/`Cat`/`Bird` + `Owner`(필드 다형성) + `Zookeeper.feed(Animal)`(매개변수 다형성).
- **P4추상클래스:** Pet/Puppy/Turtle → 추상 `Animal`(abstract sound/move, 공통 sleep) + `Dog`/`Cat`/`Bird`. "P1의 구체 Animal → P4의 추상 Animal"로 자연스러운 진행.
- **quest(Q1~Q4):** 이미 Animal/Shape/Vehicle 도메인이라 그대로 + 아래 4번에서 A~F 전 섹션 보강.
- **검증:** corretto-17 컴파일 통과, 5개 main 실행하여 다형성 출력 정상 확인(강제타입변환Main은 의도된 ClassCastException).

## 4. [확장] 소스 quest에 문제 정답 채우기

**지시:** 소스 quest도 문제 정답 만들어줘.

문제 문항 대비 quest 소스가 20~30%뿐이던 것을, 답안 문서(`docs/java_basic/문제답안/chN_문제답안.md`)를 정답 기준으로
**runnable `SolutionX.java`로 이식**. 문제 섹션(A,B,C…)별 1파일, `package quest;`, main 포함.

- **신규 149개 파일**(ch2~ch16), 전체 quest 파일 211개. 기존 Q1~Q4는 삭제/변경 없이 유지(중복 섹션은 스킵).
- 챕터별 신규: ch2(6) ch3(7) ch4(8) ch5(6) ch6(5) ch7(8) ch8(7) ch9(10) ch10(16) ch11(8) ch12(16) ch13(14) ch14(16) ch15(10) ch16(12)
- 순수 설명/비교("설명하시오/비교하시오/설계 논의") 섹션은 코드가 아니므로 스킵(날조 금지).
- **검증:** 15개 챕터 quest 폴더 전부 corretto-17 `-encoding UTF-8` 컴파일 클린(기존 Q + 신규 Solution 동시 컴파일).
- 특기: ch9 커스텀 예외는 전부 RuntimeException(unchecked)로 챕터 방침과 일치. ch15는 학습용 플레이스홀더 접속정보만 사용(F-3 HikariCP 예제는 외부 의존성이라 스킵). ch16은 안정 Java 17 문법만(타입 스위치 패턴 미사용), 데드락 예제는 안전 순서로 종료되게 처리.

## 5. [정리] 강의 흐름에 맞게 파일 정리

**지시:** 무슨 말인지 모르겠으니 강의 흐름에 맞게 알아서 정리.

- **ch12 빈 스텁 3개 → 동작 예제로 채움**(강의 흐름=해시/컬렉션 실습에 부합):
  - `해쉬예제/완주하지못한선수` — HashMap 카운팅(프로그래머스 유형)
  - `해쉬예제/폰켓몬` — HashSet 중복 제거 + `min(N/2, 종류수)`
  - `리스트/로또중복없이List메인` — List.contains로 중복 없이 6개
  - 3개 모두 컴파일·실행 검증(출력 정상).
- **ch5 P1메모리영역 near-중복:** `P1메모리영역`(축약형)과 `P1메모리영역2`(`new int[]{}` 정식형)이 결과 동일 → 삭제 대신 `P1메모리영역2`에 "표기법 차이" 주석 추가로 존재 이유 명확화. `P1메모리영역3`(별칭/참조 복사)은 별개 주제라 유지.
- **ch3 P6 3파일:** `P6비교논리연산자`/`P6비교논리연산자2`/`P6삼항연산자` — 각각 비교·논리·삼항으로 주제가 달라 모두 유효 → 유지.
- ch11 P2/P3/P5의 빈 클래스(Building/Food/Animal/Cat/Dog/Human/Student/Worker)는 제네릭 경계타입 데모용 의도적 fixture → 유지.

## 6. [수위] 문제 어휘 수위 조정

**지시:** 크게 상관없으니 수위 조정만.

검수가 지적한 "초보 수위 초과" 지점(레이어드 아키텍처/실무 설계 어휘)을 심화 표시 + 쉬운 풀이로 완화.

- **ch9 문제 E·F:** 제목에 "(심화)" 표기 + E 앞에 안내 블록("실무 맛보기 — Repository=데이터 저장, Service=업무 로직… 어려우면 건너뛰어도 됨, A~D 우선"). §9(예외 변환)은 2차에서 이미 완충 문구 있음.
- **ch10 §7 실무 패턴 → "(실무 미리보기)"** + UTC/ISO-8601/Clock 주입을 초보용 한 줄 풀이로 설명.
- **ch10 §8 대용량 파일 처리 → "(실무 미리보기)"** + OOM/스트리밍/버퍼/Flush를 쉬운 말로 부연.
