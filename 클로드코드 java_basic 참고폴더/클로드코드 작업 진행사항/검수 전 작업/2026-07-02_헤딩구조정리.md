# 헤딩 구조 정리 (2026-07-02, 3차 작업)

## 작업 배경

챕터 폴더들을 md 파일 하나로 합칠 때(flatten) 남은 흔적 때문에 문서 구조가 꼬여 있었음:

```
# ch3_연산자        ← 문서 제목
통합 문서입니다.     ← 합치기 작업 안내문
## 1. 연산자        ← 파트 구분용 "래퍼" 헤딩
# 연산자            ← 옛 파일 제목(H1)이 그대로 남음 (## 아래에 #가 오는 역전 구조)
## 1. 연산자란      ← 실제 내용 (래퍼와 번호까지 겹침)
```

확인 결과 ch3/ch4만이 아니라 **ch3~ch16 전체**에 같은 패턴이 있었음.

## 정리 규칙 (전 챕터 일괄 적용)

1. **`통합 문서입니다.` 안내문 제거** — 독자에게 의미 없는 작업 메모
2. **래퍼 헤딩 제거** — H1 바로 앞에 오는 `## 1. 연산자`, `## 2. 문제` 같은 파트 구분용 헤딩 전부 삭제
3. **중복 H1 제거** — 문서 제목과 같은 내용인 옛 파일 제목 H1 삭제 (예: ch3의 `# 연산자`)
   - 단, **진짜 파트 제목은 유지**: ch5(`# 메소드와 스코프` / `# 배열`), ch10(날짜시간/문자열/입출력), ch16(최신문법/멀티스레드/학습가이드)처럼 한 챕터에 여러 주제가 합쳐진 경우와, 모든 챕터의 `# 문제` 구분자는 남김

### 정리 후 구조

```
# ch3_연산자        ← 문서 제목
## 학습 목표
## 1. 연산자란      ← 바로 본문 시작
## 2. 산술 연산자
...
# 문제              ← 이론/문제 파트 구분 (전 챕터 공통)
## A. 기초 문제
```

## 추가로 함께 정리한 것

- **ch1에 frontmatter 추가** — ch1만 `layout`/`title` 메타데이터가 아예 없었음 (다른 챕터와 통일)
- **전 챕터 description 정비** — `description: ch3_연산자 통합 문서` 같은 무의미한 값을 각 챕터 내용 요약으로 교체 (예: ch3 → "산술/비교/논리/비트/시프트/삼항 연산자와 평가 규칙"). HTML meta 태그와 검색 결과에 노출되는 값

## 검증

- 래퍼 헤딩(`## N.` 뒤에 H1이 오는 패턴) 잔존 0건 확인
- `통합 문서입니다.` 문구 잔존 0건 확인
- 내용(본문/코드/이미지)은 변경 없음 — 헤딩·메타데이터만 정리

## 검토 포인트

- `git diff docs/java_basic`에서 각 파일 상단(frontmatter~학습 목표)과 `# 문제` 직전 부분만 보면 됨
- 사이트 렌더링 시 목차/헤딩 크기가 이전과 달라 보이는 것이 정상 (역전돼 있던 구조가 바로잡힌 것)
